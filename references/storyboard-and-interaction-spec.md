# 故事板与交互状态规范

用于 `video_led_web` 课程设计阶段的可感知交付。它不是正式媒体验收，也不取代视频生产计划。

## 故事板最低列

| 列 | 必填内容 |
|---|---|
| `shot_id` | 稳定镜头标识和所属 Beat |
| `duration` | 计划时长或待实测标记 |
| `frame` | 景别、机位、构图、主体占比、前中后景和手机安全区 |
| `action` | 人物、相机、对象和信息揭示的实际动作 |
| `dialogue` | 逐句旁白/对白或明确的无声状态 |
| `learning_evidence` | 学习镜头承担的可观察证据；纯体验镜头按下方用途规则登记 |
| `transition` | 进入、切换、暂停、分支、返回和接缝状态 |
| `asset_status` | `planned`、`prototype`、`accepted` 或 `blocked` |

`learning_evidence` 按[内容质量 owner](content-design-quality.md)区分学习与体验作用；纯氛围镜头可记录无必需学习证据，另写具体体验目的、删除损失和注意约束。体验作用不代替目标覆盖。

“电影感”“展示地图”“人物讲解”等抽象描述不能替代具体画面、动作与用途。

填表时先写行动前可见的材料和条件、暂未揭示的信息、取得证据的动作与揭示位置，再写学习者能完成的判断和回应。若旁白在独立选择前已给答案，将该任务如实记为验证/应用，或调整揭示时机。信息是否泄题与理解是否成立需要实际内容审阅，字段齐全不证明。

生成/修订后，按[分镜独立审阅](storyboard-review.md)读取实际对白、动作与全部适用分支，保存正文位置、当前字节与发现。承诺和下一镜的响应按 narrative owner 核对；结构表和作者解释不替代实际审阅。

预演格标明“独立镜头”或“同镜时刻”，与 source→target 区间分别计数；一个多镜生成输出不按格数重复装配。参考职责、生成单元和提交读回分别进入视频生产系统对应 owner，不新增第二张同义表。

## 互动状态最低列

| 状态 | 必填内容 |
|---|---|
| `entry` | 视频帧、对象、触发条件、热区位置和安全区 |
| `open` | 进入后的第一屏、当前问题、必要材料和操作说明 |
| `working` | 操作中的对象变化、暂停音频、字幕和草稿状态 |
| `feedback` | 正确、错误、求助或不确定时的视觉、声音和知识反馈 |
| `revision` | 学习者如何改线、改句、重做或补证据 |
| `return` | 返回时间、画面、字幕、声音、焦点和后续事件 |

动态背景或精确对象热区触发[呈现、背景与锚点契约](video-presentation-contract.md)：设计稿登记场景/对象映射，正式视频接入后以实际 PTS 和解码尺寸编译；参与计划引用同一 presentation anchor。计划时间与坐标保持 planned，实际接入后完成暂停、投影、遮挡和恢复验收。

## 交付边界

设计阶段可以没有最终 MP4、TTS、3D 或 360°文件，但不能没有它们的体验契约。正式媒体的文件、哈希、生成任务、成本、编码、听审和浏览器运行证据进入生产与验收阶段；本文件只描述应当如何被感知和连接。

## 设计稿自检

- 每个必需 Beat 都有至少一个可评审镜头序列。
- 每句关键旁白都有画面或对象证据。
- 每个必需互动点都有入口帧、第一屏、反馈帧和返回帧。
- 热区不遮挡脸、手、字幕、关键史料或必要数据。
- 互动延伸视图说明为什么需要它，以及为什么更低成本表征不足。
- 没有把 `planned` 媒体写成已制作或已验收。
