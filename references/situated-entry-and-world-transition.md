# 情境进入与世界转换

沉浸式课程应使学习者理解当前对象、关注它的理由和参与方式。简短课程定位、自然问候或已有知识的观察问题可以先出现，但不能代替场景与知识关系。按 `imagineering-for-learning.md` 借鉴主题体验的连贯性，不把“现实→事故→穿越→授予身份→操作”变成固定脚本；正常演示、安静发现、创作与取舍都可成立。

## 先由主持者完成世界启动

默认学习者对当前情境是零背景输入。用场景匹配的接入通道建立对象用途与行动关系：角色型课程可从正在发生的事务切入，以回应、注视或协作让学习者在场，不强制问候和自我介绍；没有人物合理性的课程可用旁白、界面或对象反馈。低门槛第一动作前须理解该动作，首个学科任务前须补足其所需背景。

主持者必须完成以下功能，允许与触发事件和身份落地融合：

- 说明此处是什么、当前对象是什么，以及系统通常要完成什么。
- 让学习者知道地点、工作现场或模拟区域及其用途；实际入场说明、空间与自然对白可以共同承担，不强制说欢迎语。
- 说明当前事务的任务目标、最后产出和参与顺序，让学习者知道自己要完成什么，而不是只知道“有异常”。
- 用新手可理解的语言建立最小世界模型和首动作所需术语。
- 交代参与权限、当前动作与最终产出，不强制预告观察、尝试和修订的步骤链，不泄露答案路线。
- 说明学习者与主持者各自负责什么，避免 NPC 既给资料又代替学习者判断。
- 用实际台词和对象动作把说明交给第一项有效行动。
- 明确无需预先知道的内容，以及不理解时可取得的基础支持。

“欢迎来到……”“情况紧急”“现在开始任务”不能单独承担世界启动。NPC 与场景、事务和后续反馈必须匹配；片头人物若在后续消失，仍然只是包装。上述条目是信息覆盖要求，不能依次转写成 NPC 台词。入场说明、现场行动、自然对白、对象与支持共同完成定向；剧情人物为当前事务说话，首个学科任务前保证必要信息已实际呈现。创作披露可在入场说明承担。

## 通用进入链

按内容组织以下七个功能，不要求七个独立镜头或固定时长：

1. **现实锚点**：从学习者能理解的地点、物件、消息、问题或日常操作开始。说明此刻通常应发生什么，不假定其拥有特定生活经验。
2. **进入理由**：变化、委托、发现、创作愿望或未完成结果使当前问题值得关注；也可来自正常运作中需要解释的现象，无须打断常态。沿用 `inciting_event` 字段记录实际缘由，不为字段制造事故。
3. **连续接入**：有空间尺度、时间、视角或对象状态变化时保留连续线索；无此变化则保持原场，沿用 `threshold_transition` 写明关注对象、证据或操作状态的自然接入，不强制独立过渡镜头。
4. **身份落地**：通过人物回应、工具权限、工作位置或对象移交确认学习者现在能做什么。身份是行动权限和责任，不是只显示称号。
5. **第一项有效行动**：无需猜未教知识，产生有用观察记录、解释修订或对象变化。可接在必要示范后，不要求开场立即操作；点击“开始”、看完动画和选择头像不算掌握或有效知识行动。
6. **持续载体**：同一物件、记录、地图、样本、仪表、作品或证据容器贯穿教学、练习、反馈与结课，保存学习者行动留下的痕迹。
7. **世界规则连续**：开场建立的对象、目标、限制和反馈方式继续约束后续任务。进入后突然切回普通题库、通用卡片或无关奖励会破坏情境。

课程定位、必要背景、最小世界模型、学习路径预告和学习用途仍须在首个学科任务前实际可听或可读。情境不能用悬念隐藏学习者需要知道的内容，也不能提前泄露后续答案。

### 场景简报的可制作写法

设计稿不能只写“NPC 介绍背景并发布任务”。至少拆出以下信息，并为每项绑定台词、画面对象或状态：

| 简报段 | 最小内容 | 现场承接 |
|---|---|---|
| 地点接入 | 地点及其可辨认特征，不要求欢迎语 | 入场说明、NPC 回应、镜头定位、空间标签或文本等价 |
| 场景用途 | 这里平时处理什么、当前对象属于哪一环 | NPC 指向设备、资料、人物、环境或界面区域 |
| 身份与关系 | NPC 的职责、学习者的行动身份和权限 | 工具移交、工作位置、权限变化或可回应动作 |
| 事务与问题 | 正常状态、当前变化、为什么现在要处理 | 原始资料、现场结果、消息或对象状态变化 |
| 任务与产出 | 要解决的具体问题、参与步骤、最终提交/完成物 | 质检单、地图、作品、记录、报告或结果面板 |
| 支持与交接 | NPC/系统提供什么，学习者保留什么判断；第一动作是什么 | 道具推到面前、扫描、标记、核对、观察或校准 |

这些信息可分配到入场说明、动作、对白和对象，不必全部由 NPC 说出，更不能只把长简报拆成几段。对长课程，知识背景可随任务补充，不能派一个学习者无法理解的学科任务。

## 选择进入强度

| 强度 | 适用条件 | 最小表现 |
|---|---|---|
| `compact` | 单一概念、短课、熟悉情境或低制作预算 | 一个现实对象触发变化；共享对象完成视角或状态转换；身份与第一动作在同场落地 |
| `standard` | 多阶段机制、角色协作、需要工具或持续记录 | 所需背景、关系与连续接入充分成立，可以同场融合，不强制独立阈限段；对象状态贯穿主线 |
| `extended` | 长课程、复杂系统、强空间探索或多个任务区 | 多步进入与可回访中转区；仍需尽快开放第一动作，不用长片头推迟参与 |

按学习价值、内容复杂度、设备和制作能力选择强度。`extended` 不自动更沉浸，`compact` 也不能退化为标题页。

## 阈限过渡怎么成立

先决定学习者需要感知的变化，再选择媒体：

- 微观机制可用同一液滴、扫描点、切面或追踪信号把现实物件转成内部空间。
- 历史与地理可用同一地点、档案、声音或物件完成时间和视角切换。
- 数学与抽象关系可让现实数据、路线或装置转换成可操作模型，不必虚构奇幻传送。
- 语言与技能课可从真实沟通、作品或工作失误进入模拟现场。

至少写清转换前状态、连续线索、感知变化、转换后状态和开放动作。音乐、粒子、镜头冲刺或黑场本身不构成阈限；没有对象连续性时，它们只是片头装饰。

## 第一动作与持续载体

第一动作满足四项：

- 学习者理解为什么现在做。
- 不要求掌握尚未教过的学科结论。
- 结果在现场可见，并改变下一步。
- 后续能引用这次动作留下的对象状态或记录。

可选择有目标的观察位置、标记一次变化、形成初步比较、启动必要追踪或调节模型。接过资料、核对封签和校准只有在改变后续取证/理解条件时才值得保留，不因“像在现场”而默认添加。避免“接受任务”“点击继续”“选择阵营”“收集无关积分”等只改变界面的动作。

持续载体承担情境记忆和学习记录。每次教学阶段应回答：它新增了什么证据、状态或修订；人物如何读取它；结课如何用它完成事务。载体不必永远占屏，但恢复后状态必须一致。

## 跳过、重看与等价路径

首次进入可以提供“跳过动态，直接进入当前状态”，但不能跳过必要背景、身份、对象状态和第一动作。跳过后用短文本、静态前后图或确定性状态切换补齐同义内容。

同时设计：

- 静音字幕和声音线索的视觉等价。
- `prefers-reduced-motion` 下的分步静态转换，不使用快速缩放或持续视差。
- 媒体失败时保留对象和恢复状态，按资源准入规则重试/阻止推进；不能把静态低配替代称为正式体验继续。
- 重看入口，不清空首答或持续载体。
- 恢复入口，说明“你正在处理什么、已经留下什么、下一步是什么”，不整段强制重播。

## 脚本与蓝图要求

新课和重大沉浸入口改稿使用 `opening.contract_version=1.2`。先在 `opening.orientation_bootstrap` 填写：

- `assumed_entry_state`
- `host_welcome`
- `minimal_world_model`
- `key_objects_and_terms`
- `learning_journey_preview`
- `role_and_collaboration`
- `first_action_handoff`
- `comprehension_safeguard`

再在 `opening.experience_entry` 填写：

- `intensity`
- `reality_anchor`
- `inciting_event`
- `threshold_transition`
- `identity_landing`
- `first_consequential_action`
- `persistent_carrier`
- `world_rule_continuity`
- `accessibility_equivalent`
- `skip_replay_reentry`
- `design_rationale`

这些字段写实际内容、台词和状态，不写“NPC介绍背景”“营造沉浸感”“播放转场视频”等占位描述。`information_units` 仍负责声明迎接、世界模型、路径预告、课程定位、背景、问题、角色和首动作何时实际呈现；三套字段不能互相替代。

保留历史字段名兼容性：`host_welcome` 登记实际接入关系，`learning_journey_preview` 登记参与与产出定向；`inciting_event` 可为正常现象或创作缘由，`threshold_transition` 可为同场连续接入，`first_consequential_action` 引用首次有意义参与的真实位置。不得留空或用“不适用”逃避必要定向，也不为了字段添加事故、欢迎语、转场、交物或步骤对白。结构检查只验证内容与时序声明，剧情质量另审。

课程设计和媒体计划至少给出“现实状态→触发→阈限→身份→第一动作→主线”的进入序列，以及持续载体在各阶段的状态。评价与核对分别检查理解、定向、突兀、等待过长和情境断裂。

## 准出问题

内容评审逐项回答：

1. 去掉课程标题后，学习者能否仅凭事件理解为什么此刻进入？
2. 前后世界是否共享一个可追踪对象、声音、动作或问题？
3. 学习者身份是否改变其可执行动作，而不只是称号？
4. 第一动作是否改变现场，并被下一场引用？
5. 开场规则、载体和角色关系是否至少持续到一次核心练习和结课？
6. 跳过、静音、低动态、媒体失败和恢复是否落在同一状态？
7. 进入时长是否挤压学习，或在动作开放前堆积过多信息？
8. 零背景学习者能否仅凭开篇理解世界、对象、正常状态、学习路径、角色分工和最终产出？
9. NPC/主持者是否先建立可回应关系，再把说明自然交到第一动作；还是只欢迎、下命令或播完即消失？

浏览器验收记录转换前后截图、操作、持续载体状态、低动态/静音/跳过/恢复结果。真实试学观察学习者能否说清“我在哪个事务里、我现在是谁、为什么做、第一步改变了什么”，以及是否因转场或信息量迷失。结构校验只证明字段完整，不证明情境有效。

## 常见失败

- 电影片头之后切到普通课程首页。
- 默认学习者已经理解世界、对象和术语，只用一句任务命令开始。
- NPC 只说 hello、宣布危机或列课程目录，没有最小世界模型、角色协作和首动作交接。
- 角色宣布身份，但学习者没有对应工具、权限或责任。
- 第一动作只是播放、继续或领取徽章。
- 用无关灾难、倒计时或军事命令制造紧张。
- 阈限只换颜色和音乐，没有对象或状态连续。
- 开场一次性出现地图、全部任务和奖励系统，推迟实际参与。
- 持续载体只是 HUD 装饰，不保存证据或影响人物回应。
- 跳过后缺背景，恢复后强制重播，低动态路径丢失状态。
