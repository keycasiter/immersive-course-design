# 体验设计：把理解落实到经历

先读[内容与语境](content-and-context.md)核对来源与学科边界，再围绕本课最值得亲历的关系设计。完整稿应让读者看到学习者真正经历什么；制作推进与确认见[生产流程](production-workflow.md)。

## 从核心关系选择情境与参与

| 决定 | 要写出的内容 | 判断是否成立 |
|---|---|---|
| 核心理解 | 哪个现象、词句、因果/空间关系或人物处境值得亲历；依据及解释边界 | 能说清这段经历使哪一关系更可感知 |
| 情境与视点 | 学习者在哪里、为何注意当前对象、从哪里观察 | 地点/视点改变可见信息或参与条件，且与内容相连 |
| 关键感知 | 实际细节、声音、对照、尺度或变化；先后顺序与停留 | 画面与对象行为自身提供线索，说明文字帮助回看 |
| 主动参与 | 观察、查看、靠近、换视点、跟随、操作、对话、自然选择或阅读 | 动作与对象关系具体；安静观察段不被强塞点击 |
| 现场回应 | 对象/人物/环境如何变化，如何回到同一事件并继续 | 选择有可见后果；固定叙事也保留合理探索与退出 |

先写关键经历再选功能，避免按技术菜单拼课。比如“理解面积守恒”可以落实成同一块纸在剪开、平移、拼合前后始终可追踪；“沉浸式互动展示公式”尚不足以指导制作。跨题材时重新选择表征，不照搬纸片或拖拽。

## 完整主稿的五个部分

### 入口：建立最小背景

写实际首屏和第一句台词/说明，交代这里是什么、当前对象/人物是谁、可先做什么、为何值得看。通过现场建立方向；不假设学习者已认识人物或符号。独立代表场景也保留最小背景，不统一套长简报或危机。

### 经历：把每场写到可感知粒度

每场按下表填实际内容；场数由必需内容与自然接续决定。

| 部分 | 填写要求 |
|---|---|
| 开始状态 | 现有对象/人物、视点、已知信息、上一段留下的状态 |
| 画面与声音 | 真实可见细节与变化，实际对白/旁白/可读资料；无声段写必要信息如何可见 |
| 参与与回应 | 入口/邀请、动作目标、操作窗口、对象或人物的实际响应、可见后果 |
| 接续与返回 | 何时自然继续、什么状态保留、可选探索如何退出并回到当前对象 |
| 理解联系 | 这一段的感知/事件对应哪个内容项；创作/演示近似在哪里说明 |

台词写成可直接说出的句子，资料写出真正需阅读的正文。镜头与动作补到事件触发、锚点和前后状态；有复杂角色/运镜时读[情境与分镜](situation-and-storyboard.md)。每一视点变化都要说明它让哪个关系看得更清楚。

### 节奏：观察与行动有各自空间

关键变化前给注意线索，发生时保留可看清的时段，发生后允许比较或重看。等待操作时世界处于合理状态，不要求抢点。可选细节不限制主线，自然选择不必分叉整段剧情。说明文字、旁白与对象变化避免同时争夺注意；根据本课内容决定安静与参与的比例。

### 结束：让经历回到内容

用已发生的对象变化、人物回应或前后对照收束，允许自然重看或带走观察记录。观察段在关键事件实际呈现后可接续；探索可退出并保留状态；对话/选择按现场回应继续；阅读保留位置。推进条件只反映这些现场事实，不设置隐藏知识判分。

### 设计自查：逐项回到依据与感知

对照必需内容清单，逐项定位到场景与感知细节；核对陌生读者能否找到首动作、辨认对象并复原前后变化。删去无解释作用的装饰/背景，改写含糊响应，补齐仅靠声音或颜色表达的必要信息。内容正确由作者核对，学习者体验按[真实走访](experience-review.md)另行观察。

## 主稿转入生产计划

纯设计任务用上述完整主稿交付。进入制作、工程入口可核对时，按[场景契约](scene-contract.md)转入 `scene-plan.learning`，从计划编译 `experience.md`；此后只改计划，不并行维护第二份语义正文。画风、视点与设备约定进 `presentation`；代码/绑定进 `implementation`；实际验收另存生产清单。
