# PBL 前置适配筛分

本文件用于在课程设计前判断是否采用 PBL。Imagineering 默认作为体验/生产层候选；PBL 只有在学习目标、内容结构、使用场景和资源条件满足时才启用。

## 1. 基本判断

### Imagineering 的适用面较宽

只要课程需要把知识放入一个可感知的体验中，并且存在世界、对象、行动、反馈或工程约束，就可以考虑 Imagineering：

```text
世界/情境
→ 对象/资料/人物/环境
→ 学习者行动
→ 可感知反馈
→ 原型、测试或修订
```

它可以用于：

- 知识理解；
- 观察和比较；
- 历史/文学情境；
- 科学现象；
- 技能练习；
- 空间和对象探索；
- 短时互动体验；
- 完整项目课程。

使用 Imagineering 不等于必须使用 PBL，也不等于必须产生公开作品。

### PBL 的适用面是条件性的

PBL 适合把学习组织为一个持续项目，但不是所有学习目标都需要项目化。完整 PBL 至少要有：

1. 需要探究和解释的驱动问题；
2. 足够的持续时间；
3. 与学科内容结合的资料和实践；
4. 学习者有真实的选择；
5. 一个跨阶段形成的作品；
6. 反馈、批评和修订；
7. 真实或有意义的受众/公开产品。

缺少核心条件时，不要为了“沉浸”或“有作品”强行称为 PBL。

## 3. 学习内容筛分

| 内容/目标特征 | PBL 建议 | 原因 |
|---|---|---|
| 需要查资料、比较证据、解释复杂问题 | 适合完整 PBL | 有持续探究和开放解释空间 |
| 需要设计、制作、实验、调查或解决真实问题 | 适合完整 PBL | 能形成真实作品和受众 |
| 多学科知识需要综合使用 | 适合完整 PBL | 项目可以承载跨学科整合 |
| 有多个合理方案，质量可用标准评价 | 适合完整或受限 PBL | 可以体现选择、批评和修订 |
| 需要先掌握基础概念，再完成作品 | 先教学后项目化延伸 | 基础知识不必全部项目化 |
| 目标是比较、解释或短时论证 | 受限 PBL/项目化任务 | 可有小型作品，但不一定需要长周期项目 |
| 目标是程序熟练、基本事实或术语记忆 | 通常不启用完整 PBL | 先用示范、练习和反馈建立基础 |
| 有唯一正确步骤、强收敛答案和严格安全要求 | 通常不启用完整 PBL | 需要直接指导、演练和确定性评价 |
| 只需要观察一段过程或理解单个概念 | 通常不启用完整 PBL | 可使用 Imagineering 和视频互动 |
| 内容敏感、高风险或不适合开放模拟 | 谨慎使用或不启用 | 需限制角色权限、资料和结果空间 |

## 4. 场景筛分

### 适合完整 PBL

- 有 2 个以上学习时段或足够的单次学习时间；
- 学习者可以查找、比较或回访资料；
- 有明确的作品保存和版本修订能力；
- 有教师、同伴、专家或模拟真实受众反馈；
- 评价不仅看最终答案，还看证据、过程和修订。

### 适合受限 PBL

- 时间较短，但问题和作品仍有开放空间；
- 作品可以在一个课程单元内完成；
- 反馈和修订至少发生一次；
- 公开产品可以是小型导览、解释卡、模型或演示。

### 不适合完整 PBL

- 只有一次短时观看；
- 学习者没有资料、选择或作品；
- 内容必须按固定顺序快速掌握；
- 没有真实或有意义的受众；
- 最终答案在课程开始时已经完全确定；
- 没有时间进行反馈和修订；
- 开放探索会增加错误、误解或安全风险。

## 5. 决策输出

筛分只能输出以下四种状态：

### `pbl_full`

具备完整驱动问题、持续探究、作品、选择、反馈修订和公开产品。可以读取[Imagineering × PBL 整合框架](imagineering-and-pbl-integration.md)。

### `pbl_bounded`

保留项目问题和作品，但缩短周期、限制资料范围、限制选择空间或采用模拟受众。必须明确哪些 PBL 要素被缩小。

### `project_extension`

课程主体先完成基础知识和技能学习，最后增加一个项目化应用。不能把前面的讲解和练习整体称为 PBL。

### `imagineering_only`

使用 Imagineering 组织世界、对象、行动、反馈和媒体，但不要求持续项目、公开产品或长周期探究。

## 6. 最小判定规则

### 启用完整 PBL 的必要条件

以下四项缺一不可：

- 有真实或有意义的驱动问题；
- 有跨阶段持续形成的作品；
- 有持续探究，而不是一次选择；
- 有真实/模拟真实受众或公开展示。

同时还应具备学习者选择、反馈修订和反思；如果它们只能由系统自动完成，降级为 `pbl_bounded` 或 `project_extension`。

### 只启用 Imagineering 的条件

以下任一情况成立时，优先使用 `imagineering_only`：

- 目标主要是观察、理解、练习或即时反馈；
- 学习时间短，不适合持续项目；
- 内容高度收敛或必须先直接教学；
- 没有合适的真实受众和公开产品；
- 学习者不需要形成跨阶段作品。

这不是降低课程质量，而是避免用错误的教学框架包装课程。

## 7. 与视频主线的关系

无论选择哪种状态，`video_led_web` 都可以作为运行形态：

```text
Imagineering only:
视频事件 → 对象/互动 → 即时反馈 → 返回视频

Project extension:
视频事件 → 基础教学/练习 → 最终项目任务

Bounded PBL:
视频事件 → 子问题探究 → 作品局部更新 → 反馈修订 → 返回视频

Full PBL:
视频事件 → 持续探究 → 作品版本推进 → 批评修订 → 公开展示
```

视频主线不决定是否采用 PBL；PBL 适配筛分决定教学层，`video_led_web` 决定运行层。
