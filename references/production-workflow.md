# 从内容到成品的生产流程

按当前请求的交付边界执行；已经完成且仍有效的阶段直接沿用。每阶段收口产物后再扩展，修复任务走末尾的局部变更路径。数据字段见[场景契约](scene-contract.md)，确认与证据字段见[生产与版本](production-and-version.md)。

## 1. 核对依据，写完整体验

**输入**：用户材料、已有项目/设计、学习者背景、设备与授权范围。

先按[内容与语境](content-and-context.md)整理内容证据：采用的事实/规则、可定位来源、创作或近似、未知项、将在哪一场呈现。只有主题时提出具体方案，来源尚未核实时标记待核；不声称已对齐某教材。

然后按[体验设计](experience-design.md)写完整主稿：

1. 选出值得亲历的关系，说明为什么空间、时间或参与能使它可感知。确定观察位置和学习者能做什么。
2. 从首次进入写到结束，填实际画面、可读资料/台词、声音或无声设计、对象前后状态、参与窗口、现场回应和接续。按[页面与注意力](page-and-accessibility.md)写清默认画面的关注点，以及详细内容/工具的进入、收起和返回；避免只交“探索区、互动区”等栏目名。
3. 对照内容清单逐项定位到场景和可感知细节；把纯装饰、重复讲述或不能实现的选择改成具体内容。无人物/无旁白设计同样写清首动作和关注点。

**产物与收口**：陌生读者能从主稿复原完整经历，内容有依据，主要参与有动机与响应，目标设备和等价路径明确。只做设计时可交此稿，不为填写实现字段创建工程或编造版本。进入制作时把语义转入下一阶段的唯一计划；原散稿标记为历史，不再并行手改。

## 2. 建立计划，完成设计确认与实现交接

**输入**：完整设计、当前工程的真实结构与依赖；先读取[场景契约](scene-contract.md)、[运行契约](runtime-contract.md)和[页面与注意力](page-and-accessibility.md)。

### 填写顺序与数据去向

| 顺序 | 实施动作 | 落点/核对 |
|---|---|---|
| 内容与场景 | 从内容清单建立对象/人物/规则、场景、事件、互动及可达接续；分配稳定 ID | `learning`，实际文字只写在此处 |
| 表现约定 | 明确主形/尺度、材料/光照、机位、设备视口、人物/声音身份，以及默认/操作/阅读状态中的信息与安全区 | `presentation`，写能观察的目标；信息出场对应既有场景/事件，不维护第二份正文 |
| 运行接口 | 核对锁定 Three.js 版本与工程入口；决定模型求值、动作、快照、恢复、时钟与资源生命周期 | `implementation`；计划中的函数名必须落实到代码 |
| 资产与测试 | 登记实际采用的资源；为需要执行验证的规则指定测试与源码 | `resources`、`rule_bindings`；全部规则都有绑定，`source_review` 也需要 |

复制 `assets/scene-plan.template.json` 到课程工程的 `scene-plan.json`，逐项填写真实内容。每个互动都有同 ID 的 `bindings`，每个场景都有 `scene_views`；未出现的角色和资源保持空数组。样例见[完整实施示例](worked-example.md)。

以下命令从课程工程执行，`<skill-root>` 替换为实际 Skill 目录；检查器不会创建源码、声音或真实确认。

```bash
python3 "<skill-root>/scripts/validate_experience.py" scene-plan.json
python3 "<skill-root>/scripts/compile_experience.py" scene-plan.json --out derived
```

编译生成 `derived/experience.md` 与 `derived/scene-index.json`。审阅可读主稿是否准确复现设计；之后语义修改回写计划再编译，运行索引只提供 ID/接续索引，不含完整台词与对象定义，不能单独当作控制器输入。

### 集中确认与交接

复制 `assets/production-manifest.template.json`，核对课程身份与代表场景 ID；保持真实草稿状态。按[生产与版本](production-and-version.md)生成设计指纹，把完整主稿与关键表现决定呈给用户。已有明确确认且对象未变时复用记录；缺决定时先完成可审材料和独立可做工作，确认前不推进依赖该决定的制作。确认记录只摘录真实原话/引用，不由 Agent 自签。

将交接写到可定位粒度：每个主要对象的形体/锚点、规则输入/输出、事件前后状态、互动处理函数、相机用途、声音 cue、恢复字段与验收观察点。单人可顺序承担各职责；多 Agent 仅按当前授权安排唯一写入者，上游接口和世界锚点稳定后再拆独立消费者。

**产物与收口**：计划结构有效，可读主稿保留真实设计，设计确认有效；制作人员可从 ID 追到对象、规则、处理函数和观察点，不需要再猜教学含义。

## 3. 完成并确认代表成品场景

**输入**：有效设计、表现约定、实现接口；读取[空间制作](spatial-production.md)，涉及人物/音频再读[人物声音](character-and-sound.md)。

选最能暴露主要风险的成品片段：例如关键结构/变形、近距离人物、核心操作或声音接续。选择理由来自全课风险，不按固定时长/场景数，也不另做一次性试片。

### 从规则到实际场景

1. **结构与模型**：先实现规则求值器和对象生成器，必要规则写可失败测试；确定世界单位、锚点、相机和可操作范围。固定视点检查主形、连接、体积和核心关系。
2. **状态与操作**：把完整计划接到控制器/等价实现。`act` 改对象状态，`evaluate` 据状态与时间求值，再按变化更新网格、标签、人物、显隐和字幕；复用未变的世界对象，界面显隐不重建静态几何。操作真实呈现后才 `markEvent`，不由点击/时钟自动假定完成。
3. **品质与接续**：让材料、光影、动作、页面与声音共同揭示关系。走通进入、参与、现场回应、继续/返回、暂停与恢复；在最终目标视口分别审默认画面、操作中和深读返回，核对关注点与同屏反馈，有声则实际听审。

灰模/局部对照用于定位问题，代表场景交付时须达到候选最终品质。按[验收](validation.md)为该范围取真实内容、视觉、动作、交互、等价路径、恢复、性能及适用的声音证据。源码改动后先复验再更新文件快照与收据，不能沿用过期摘要。

冻结候选入口、源码、依赖/资源及证据到独立路径，登记 `candidate_files`，计算代表指纹，提交实际可运行入口及审阅材料。获得确认后保留候选，不用全课后续构建覆盖它。

**产物与收口**：代表范围闭环可用，四个品质面有具体观察，候选与证据相符，代表场景确认有效。结构检查通过不足以放行成品品质。

## 4. 逐场扩展与整合

**输入**：已确认候选、共用接口与表现约定。

每场沿用“内容与前后状态 → 生成/求值 → 操作与反馈 → 声画接续 → 目标视口与操作复验”的顺序。复用对象表示、规则、材料、声音身份和控制器；各场保留自己的注意目标、动作与节奏，不整段复制代表剧情。

逐场完成后保存问题及证据，再做下一场；合并时检查共享对象与资源释放、转场/返回、全课时钟和状态恢复。全量对照 `required_content`、必需场景及实际互动，不用文件数或场景数量代表完成。

**产物与收口**：全课可运行，全部必需内容可达、互动真实可用，场景之间状态/视点/声音连续，当前文件清单完整。`production_complete` 只表示制作完成；验收状态仍由真实检查决定。

## 5. 验收与交付

**输入**：当前完整构建；读取[验收](validation.md)、[生产与版本](production-and-version.md)。

先运行本课实际相关规则测试、语法/构建和结构检查；再用 CUA/MCP 在承诺设备的目标视口查看和操作。分开审图、连续动作、声音、性能、等价参与与恢复，覆盖全部必需场景和已承诺互动。缺设备/工具的项目标未覆盖，继续独立可做检查，不伪造通过。

```bash
python3 "<skill-root>/scripts/validate_production.py" production-manifest.json --plan scene-plan.json
```

**交付**：实际启动/访问入口与版本、作品和必要源码/资源、真实验收覆盖与关键证据、已知缺口/使用条件。按请求附可读设计与生产清单；制作指纹、测试与审批信息留在制作者材料，不挤入学习者界面。只有实际获授权且执行真实学习者走访，才按[体验观察](experience-review.md)报告其感受与理解线索。

## 局部修改从哪里接续

| 变化 | 处理与复验 |
|---|---|
| 实现不符合已确认设计，如拖动后标签错位 | 定位坐标/状态/布局消费者，补复现再修；检查同类对象、目标设备、返回/恢复。设计与表现约定未变则保持有效确认；更新当前源码快照和受影响证据 |
| 学科规则、台词含义、互动后果或接续变化 | 回到第 1–2 阶段核对来源与语义，重开受影响设计及下游证据 |
| 共用画风、人物/声音身份等已确认表现改变 | 回到代表范围检验新约定并确认；全课复查依赖该约定的场景 |
| 仅新增截图/日志或文档排版 | 保留有效确认，核对证据仍绑定实际候选或当前构建，不重启全课 |

同类问题连续两次修正仍失败时，记录已确认现象与失败原因，回到规则/表示/接口定位，避免继续同层调参。
