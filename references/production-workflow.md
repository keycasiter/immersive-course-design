# 从设计到成品的生产步骤

| 阶段 | 实际工作 | 放行条件 |
|---|---|---|
| 完整设计 | 内容/来源→体验主稿、场景/角色/对象/参与和自然接续→表现约定与等价路径 | 实际内容可审阅、范围完整，design确认有效 |
| 规则与代表场景 | 结构规格/生成代码→规则/状态→画面/声音/操作闭环 | 候选最终品质，实际证据对应候选文件，representative确认有效 |
| 扩展全课 | 复用已确认表示、规则、风格与接口，完成其余必需场景 | 全量内容/参与与来源完整，逐场发现的问题闭环 |
| 全面验收 | 当前构建的真实画面/连续动作/声音/操作/恢复与设备体验 | [验收](validation.md)覆盖全部必需场景，未覆盖条件单列 |
| 走访（按授权） | 观察真实学习者的感知、参与、发现和迷路/不适 | 记录条件、版本、观察与修订，不组织考试或成绩 |

完整设计确认与代表成品场景确认是两次集中人工检查，不另设完整全课Demo、逐图片或逐对象审批。候选场景直接进入成品；全课覆盖在最终验收强制，代表场景通过不代表全课通过。

按职责确定唯一写入者：体验/内容、学科规则、主体/环境、镜头/LOOK、交互/状态、声音和集成。一个人可顺序承担，多Agent只依当前用户授权及工具规则。上游输入和世界锚点就绪后再拆独立消费者；接口变化由维护者同步，不让各模块各猜比例、时间和状态。

制作源、依赖版本和输出关联记录在当前清单。技术检查与成品感受分别审阅；局部修复查受影响部分，合并/最终验收扩大覆盖。不在方法维护时启动课程、实际生成服务或试片。旧课程原合同在Git历史保存，新2.0不自动改写其确认和记录。
