# 所有课程的开场引入

每门课程都要有实际开场，使首次观看者知道这节课讲什么、眼前对象是什么、为什么关注、接着做什么。已有课程改造同样适用。引入可融入首场，不强制独立序章、人物、固定时长或互动测验。

先按 `imagineering-for-learning.md` 确定体验承诺与学科方法的实际用途。以下启动功能是信息覆盖，不是叙事顺序；正常演示、好奇观察、创作和取舍均可开场，不要求事故、求助或工具交接。课程定位可以先简明呈现，当前必要概念可以明确教；不以“自然入戏”为由删除说明或示范。

## 默认按零背景入口设计

首次进入时，默认学习者没有收到任何当前课程世界的背景输入：不知道自己在哪里、眼前对象是什么、系统通常怎样运作、角色是谁、为什么需要参与、接下来会发生什么。课程先修只允许支持学科理解，不能代替当前场景和任务的启动；只有运行时可验证已经呈现的上文才可继承。

开篇不是“欢迎后立即派任务”，而是一组可融合的启动功能：

1. **场景匹配的接入**：有角色的沉浸式课程，由 NPC 的注视、回应、协作或对象交接建立可回应的在场关系；问候与自我介绍按情境使用，不是必说台词。无人物课程用旁白、界面或对象反馈完成等价主持，不强造角色。
2. **最小世界模型**：用新手可理解的语言说明这个系统、时代、场景或工作通常要完成什么，为什么重要，当前对象位于其中哪里。
3. **关键对象建立**：首动作会使用的名称、物件、符号、单位和状态随实物、画面或短演示逐一赋义；不能先使用后解释。
4. **参与与产出定向**：说明学习者可以怎样参与、需要完成什么以及哪里能获得支持。步骤只交代当前操作需要的部分，最终产出可由入场说明承载；不要求人物预告整套观察、判断、修订流程。
5. **角色协作合同**：学习者、NPC、系统及其他角色分别负责提供材料、观察、判断、操作或回应中的哪一部分。
6. **首动作接入**：用适合场景的对象线索、回应或简短操作提示，让学习者知道怎样作首次有意义参与；必要示范可在它之前，动作位置不由“开场必须互动”决定。记录参与产生的观察、解释或对象变化，不强制一句台词加一次交物。
7. **理解兜底**：明确“不需要预先知道什么”，并提供简短样例、重述、词义、静态图或朗读。兜底不自动算知识帮助或掌握。

这些功能可边走边讲、边看边建立，不要求长篇站立讲解。输入多少由“首次学习者是否能理解当前事件和行动”决定，而不是用秒数、句数或镜头数量控制。NPC 不能只说欢迎、称号和命令；最小世界模型也不能膨胀成百科序章。

写对白前读取[可录制台词与口语审阅](spoken-language-and-review.md)，按听者当前所知直接讲清事实、对象和下一动作。不要用“给地图补上原因”等抽象搭配、名词排比或泛论承担背景；不得仅把上述覆盖项改成口语再逐条念。正式术语与必要讲解保留，并在全课台词审阅中检查开场与后续语气一致。

## NPC 场景任务简报

当课程使用 NPC 或主持者时，以下是首个学科任务前的信息覆盖表，不是默认对白骨架。剧情课可从已在进行的现场行动切入，入场说明、对白、动作、对象与支持共同让学习者回答：

| 学习者需要知道 | 实际呈现要求 |
|---|---|
| 我在哪里 | 地点、时代和环境能在入场说明、画面或自然对白中对应；不能只报抽象世界名，不强制“欢迎来到……” |
| 这里通常做什么 | 说明这个地点/系统的正常用途、服务对象和当前对象在其中的位置；只给理解当前事件所需的最小背景 |
| 我是谁、谁在和我说话 | 通过工作位置、协作动作、简短说明或自然称呼建立双方职责；学习者有相符的行动权限或责任，不只授予称号 |
| 现在发生了什么 | 用一个可见对象、消息、结果或状态变化说明当前情况；事件必须和课程核心问题有因果关系 |
| 我们要完成什么 | 用学习者能理解的事务语言说明任务目标、完成对象和判断边界；不要只说“开始探索”“解决问题” |
| 我接下来怎么参与 | 当前可执行动作、用途和操作方式清楚，后续按事务发展开放；不必预告步骤链，隐藏答案和未到时机的分支细节 |
| 最后交什么 | 说明最终报告、选择、操作、作品或解释，以及最低成立标准；不能承诺未覆盖的能力 |
| 谁负责什么 | 明确学习者负责观察、取证、判断、操作或表达；NPC/系统负责材料、示范、追问、反馈或状态变化；不让 NPC 代替学习者思考 |
| 现在先做什么 | 用对象线索、必要提示或人物回应连接到有意义参与；需先观察/学习时说明当前观察对象，首次动作可接在示范后 |

逐项绑定实际呈现位置与时机；不要把表格转写成一段“欢迎—身份—目标—步骤”的独白。剧情开场优先写人物正在做什么、对方怎样回应、哪一动作需要学习者参与，再补齐定向信息。非剧情课程可使用清楚的主持简报；形式服从用途。

剧情可以先让一个具体未完成的行动吸引注意。低门槛协作动作不必等待完整课程介绍，但其对象、用途和操作方式必须已经可理解；首个学科判断前，必要背景仍须全部实际可获得。来源与情境创作披露可放在入场说明和资料入口，不必由角色说出。

以下内容不能替代 NPC 场景任务简报：

- “欢迎来到【课程名】”“准备好了吗”“现在开始任务”；
- 只介绍 NPC 姓名、称号或性格，不说明所在地点和现场事务；
- 只宣布“出现危机”，不说明正常状态、当前对象和学习者要解决的具体问题；
- 只列课程章节、知识点或地图，不说明学习者如何参与和最终交付什么；
- 只说“跟我来/点击继续”，但第一动作不改变任何对象或学习状态。

### 开场简报自检

- 去掉课程标题后，学习者仍能说出“在哪里、这里做什么”。
- 学习者能复述自己的身份、NPC 的职责和当前事务，而不是只记住角色名字。
- 学习者知道最终要提交或完成什么，但没有提前得到后续判断的答案。
- 每个任务目标都能追溯到开场提出的事务；第一动作不是播放、继续、选头像或领取奖励。
- NPC 的对白服务其当前目标与对方回应，重要信息有对象或行动承接；不是把课程步骤改成口语后逐项交代。
- 静音、文本替代、低动态和媒体失败仍保留地点、任务、分工、产出和第一动作的同等含义。

## 课程定位与情境背景分别成立

先写面向学习者的课程定位：本节研究什么、为什么有用、学完能自己完成什么。用实际可听或可读的短句，不用设计文档中的目标表、页面标题或“开始探索”按钮代替。能力介绍与已确认目标相符，不承诺未覆盖的能力。

再建立理解场景所需背景：系统、生活或工作通常要完成什么，当前对象在整体中有什么作用，必要名称、符号、单位与指标各指什么。已有认识只激活本任务需要的基础，基础未知时给简短样例或演示；不能把诊断未教概念当作介绍。

由背景引出尚不清楚的问题，说明有角色时谁在做什么、学习者为何参与，最后接到可理解的首个动作。可先展示一个现象吸引注意，也可边行动边介绍；首个需要学科理解的任务开放前，相关背景必须已经可获得。播放完毕、点击开始或接受任务不证明学习者已理解。

动机设计按实际缺口处理：用当前问题建立注意与相关性，用可理解的首动作和支持建立可达感，用与表现相称的反馈收束。不要为套 ARCS 固定增加悬念、奖励或四段页面；动机不能替代必要背景、讲解和练习。[LS16]

## 在设计主线之前填写

| 内容 | 必须写清 |
|---|---|
| 课程定位 | 本节主题、学习用途和学完能完成的实际动作；面向学习者的正文 |
| 背景输入 | 理解当下所需的时间、地点、系统、生活或专业背景；陌生对象和必要术语 |
| 已有认识 | 能连接的生活经验、已学知识或熟悉现象；基础不足时给等价的简短输入 |
| 问题出现 | 哪个变化、差异、目标或困难引出值得学习的问题 |
| 学习者关系 | 为什么关注这个问题，如何观察或参与；有角色时交代谁在做什么 |
| 当前动作 | 第一个可以理解且执行的观察、提问或操作 |
| 自然衔接 | 背景中的对象、事件、人物、声音、视线或动线怎样进入第一个教学场景 |
| 理解检查 | 怎样判断学习者明白背景、当前问题和行动；观察、复述或按需提示均可，不必须答题 |

另外登记零背景启动包：入口假设、实际接入、最小世界模型、关键对象与术语、参与与产出定向、角色协作、首动作交接和理解兜底。可以分布在入场说明和场景中，不能只在设计说明中存在。历史蓝图字段名 `host_welcome`、`learning_journey_preview` 保持兼容，分别承载接入与参与定向内容，不要求欢迎语或固定步骤台词。

写实际对白、旁白和画面，不能只填“介绍背景30秒”。把必要术语和符号逐项对应到介绍它的内容；已熟悉且无需额外解释时说明依据，不设置术语或镜头数量。输入量由理解需要决定，试学后调整。

## 选择与本课相称的形式

- 历史：用时代与生活变化建立背景，从普通生活或生产现场引出具体事件，人物再邀请参与调查。
- 数量或抽象关系：从能看懂的比较、变化或问题输入，建立变量含义，再进入图形、公式与操作。
- 科学机制：先说明系统正常要完成什么，再出现受阻或状态变化，进入局部结构与机制。
- 语言、技能或创作：交代沟通对象、工作目标或作品用途，通过具体困难进入示范和尝试。

这些是形式示例，不能强制每门课使用同一开场套路。学科背景与事实须按来源核对。

## 让学习者真正进入课程世界

沉浸式开场不止说明背景，还要完成从现实状态到课程世界的行动转换。按[情境进入与世界转换](situated-entry-and-world-transition.md)设计现实锚点、触发事件、阈限变化、身份落地、第一项有效行动、持续载体和后续规则连续性。按课程选择 `compact`、`standard` 或 `extended`，不以时长、镜头数量或特效多少评价沉浸。

第一动作必须无需猜未教知识即可理解，并改变对象、记录、设备、人物或下一步状态。点击开始、看完片头、选择头像或领取无关奖励不能单独承担第一动作。阈限前后至少共享一个对象、声音、动作或问题；进入后的任务、反馈和结课继续使用开场建立的身份、载体和规则，不能片头结束后切回无关题库。

没有时空或尺度转换时，保持原场连续，写明关注对象或操作权限如何自然开放，不另造“穿越”。先观察再示范的入口也可成立：观察只记录已呈现内容，后续首次有意义参与引用其实际位置，不强加独立开场操作来填字段。持续载体可以就是被研究的对象或正在形成的解释，不默认透明图纸或通用记录板。

跳过动态、静音、低动态、媒体失败、重看和恢复都应落到同一课程状态。可以跳过运动表现，不能跳过必要背景、身份关系、对象状态和第一动作。

## 衔接与信息量

可以从已发生的事切入，随行动补足理解信息；首个学科任务前须给齐当前判断所需背景。让前后画面共享对象、声音或行动线索；抽象课也需有概念和任务的连续性。角色可以边走边解释，但旁白不使用“你来到……”“你将体验……”代替背景。

保留需要探索的原因和答案，首次不预告完整路线、未来节点或最终结论。主题、学习用途、核心问题和理解当前对象所需的正常背景可以明确介绍；“隐藏未来路线”不能成为省略课程定位的理由。背景不变成课程目录、百科长讲解或知识点清单。标题、时间地点标签、欢迎语和立即派任务均不能单独承担引入。

需要连接已有认识时，不预设学习者具备某种生活经验或先修。提供简短样例、事实或演示，让基础不同的人也能理解当前问题。开场初步判断可用于了解起点；不得要求猜对未教内容才能开始。

## 完整课、独立小样与恢复入口

- `standalone`：完整课程、可独立打开的小样和无法验证上文的深链接，均自带当前范围的最小课程定位与背景。小样可说明本次只观察哪段，不必制作整课序章。
- `embedded`：确实接在已呈现内容后面时，可继承相关背景；登记父课程版本、实际已呈现内容的位置和正文、可用的回顾入口。内容文件存在或继承确认不证明学习者看过。
- `resumed`：恢复学习时核对本地记录与当前内容版本，再说明当前对象、问题和下一动作。背景未呈现、记录缺失或版本不匹配时，先展示本地等价背景，再开放任务。

可随时回顾必要背景；不能只依赖 hover、声音或不可访问的旧页面。静音、字幕、媒体失败、窄屏和键盘路径都保留同一背景含义。回顾不重置已保存答案，也不泄露未来资料。

## 从设计绑定到实际呈现

将开篇拆成适量信息单元，一段可承担多种作用，不设置段数。每项记录稳定标识、用途、正文引用、呈现场景、呈现事件、实际脚本/镜头/字幕/页面位置、关联媒体与本地文本替代。用途合起来覆盖课程定位、背景、当前问题、参与关系和首个动作。

新课和重大沉浸入口改稿使用蓝图 `opening.contract_version=1.2`，历史 `1.0/1.1` 保持兼容。1.2 的 `orientation_bootstrap` 保存零背景启动包，`experience_entry` 保存现实到课程世界的进入结构；两者不能互相替代。字段见[蓝图契约](course-contract.md)。`first_task_identifiers` 列出各入口分支最先遇到的学科任务；领路、开始播放和操作帮助不算学科任务。信息必须在每条相关路径上先呈现；同场融合时明确 `scene_enter` 或 `before_task_open`，不能到任务开放后才补背景。

制作与实现引用同一份正文，不临时另写一个缩略版本。页面契约记录信息标识到实际组件和事件的对应。浏览器从清空进度的入口开始，核对呈现顺序、字幕与文本、继承失败回退和刷新；仅有蓝图声明或页面隐藏节点不算已经呈现。

## 与评价一起设计

开场支持定位与参与，不自动算为掌握核心知识。分别检查：

1. 学习者能否说明本节研究什么、当前对象是什么、发生什么及什么仍不清楚。
2. 能否理解为什么查这个对象、问这个人物或做这个操作。
3. 是否因缺少背景而迷失，或因输入过多而忘记主问题。
4. 开场是否提前给出后续任务的答案，削弱自主思考。
5. 进入首场时是否发生无说明的位置、对象或概念跳变。
6. 现实锚点、阈限变化、身份和第一动作是否形成同一条行动链，而不是片头后重新开始。
7. 持续载体和世界规则是否进入核心练习与结课；跳过、低动态和恢复是否保持同一状态。
8. 把学习者视为零背景输入时，能否仅凭开篇说清“这里是什么、对象是什么、通常怎样运作、接下来做什么、谁负责什么、最终交什么”。
9. 有 NPC/主持者时，是否先建立关系和最小世界模型再交出第一动作，而不是只说欢迎、宣布危机或下命令。

在教学评审中逐项核对正文；真实试学可通过自然交流、复述或行动观察，记录“讲什么／对象是什么／为什么做／先做什么”的实际表现、误解及补充输入。不能强制猜对未教内容才能开始，也不把开篇理解计为学科掌握。观影满意度、点击开始和背景文字齐全不能证明引入自然。

自动校验只检查契约、零背景启动用途、内容引用、媒体引用、入口分支覆盖与声明时序。NPC 是否自然、世界模型是否足够、背景与术语是否准确、答案是否泄露由内容审阅判断；实际呈现由浏览器验收判断；理解表现由真实试学判断，未执行项分开记录。

## 跨学科边界例

- 数量关系：先介绍本节比较什么变化、图中对象与单位，再从两段路线的陡缓进入测量；不先给用于解题的计算结果。
- 科学机制：先说明系统要把什么送到哪里、为什么需要运送，再介绍追踪对象的名称和检测含义，进入当前异常或疑问；“P 已制成”不足以解释 P 的含义。
- 历史：先定位时代和普通人的工作、生活变化，提出本节要查证的问题，再交代人物与第一份材料；不把情境人物的主张当成历史结论。
- 语言或技能：先交代交流对象、作品用途和本节练习的能力，再从具体困难进入尝试；不直接让学习者修改一份用途不明的材料。

以上为方法边界例，实际知识与情境按本课来源核对，不固定开场套路。

## 蓝图与制作

在设计MD和媒体计划中保留专门的开场段，并填写蓝图 `opening`。开场融入首场时，`scene_identifier` 仍指向主线入口；完整设计不得缺少此项。

确认设计后再制作开场素材。同步验收有声/静音背景输入、字幕、人物关系和首个任务的衔接；只授权修改Skill时更新规范和模板，不自动重做已交付课程。
