# 场景主导、按需呈现的学习界面

设计首个学习者画面前读取本文件。Three.js主场景先让学习者注意当前对象和变化，网页层在需要时承载邀请、标签、正文与操作。布局由当前学习活动决定，默认以场景和当前行动为中心；资料阅读与复杂操作可以有独立的清晰工作状态。

## 从当前关注点决定出场信息

先说明“此刻看哪里、为何值得看、可以做什么、回应在哪里”，再安排控件。当前焦点可以是一组需比较的对象、原文与景象、过程前后状态，不能仅靠放大标题或堆叠说明建立。

| 信息层 | 何时呈现 | 用途结束后 |
|---|---|---|
| 当前核心 | 进入事件时呈现必要对象、感知线索与简短邀请；当前需理解的数值/单位/公式同时清楚可读 | 随对象/事件更新；避免重复解释同一变化 |
| 当前操作与帮助 | 学习者准备参与或确需指引时出现主动作或一组相关控件，反馈贴近同一对象 | 操作完成后回到观察；保留明确的再次操作入口 |
| 深入内容 | 查看原文、推导、背景、完整对白或长资料时进入可读状态 | 关闭后回到同一对象、机位和进行状态，保留阅读位置 |
| 全局工具 | 课程跳转、机位选择、重看、保存/恢复、设置与来源有稳定可发现入口，按需展开 | 收起后不常驻挤占当前事件；必要的退出/暂停入口持续可用 |

首屏通常从简短邀请开始，不设跨学科固定字数或按钮数量。比较、推理、创作确需更多信息时，应明确当前活动和信息分组；必要教学内容完整保留，有具体出场时机。缩小字号、缩窄正文、删掉讲解或移到无人发现的入口，都不能作为低密度完成依据。

## 观察、参与、阅读与返回

| 状态 | 学习者应能直接感知 | 实现检查 |
|---|---|---|
| 进入/观察 | 场景身份、当前关注对象、发生的现象与可选首动作；安静观察也可成立 | 避免让学习者先读一整栏背景才知道该看哪里；章节、参数、图例与工具不同时争夺主次 |
| 参与 | 正在改变的对象、必要操作、即时可见后果 | 桌面与窄屏均在操作时实测；滚动到控件后对象/回应离屏，不能仅按“控件可点”放行 |
| 回应/接续 | 变化发生在哪里、与当前关系有何联系、怎样继续或重看 | 文字帮助回看已发生的变化；不以长状态面板替代世界回应 |
| 阅读/对话 | 当前需要的完整文本，及其与原对象/人物的联系 | 避免多个工具/阅读面互相叠加；需要聚焦时管理模态焦点，其他内容可用有界非模态阅读 |
| 返回 | 同一对象、机位、参数、焦点与声音接续 | 资料/工具显隐属于界面状态，不触发世界重置或静态几何重建；必要暂停时依时钟策略恢复 |

场景直接拖动、旋转、靠近、测量、换视点作用于真实对象。命中和标签使用最终世界变换，文字避开关键对象、手脸和运动范围。数字与公式使用同一规则结果；当它们是当前理解的必要证据时明确呈现，不能仅为清空界面而隐藏。

信息收起依据当前用途和学习者操作，不设抢读时限。桌面悬停可以补充提示，触摸与键盘须有同样可发现的入口；关键动作不能只在悬停后出现。

## 等价参与与中断

| 场景 | 处理 |
|---|---|
| 键盘/触摸 | 主要参与能由可见焦点和原生语义控件完成；精细拖拽提供分步或选择等价；工具展开后能关闭并恢复焦点 |
| 感知差异 | 颜色不独自传达状态；对象有可访问名称，必要文字/公式不只存在于canvas纹理；静音保留必要信息 |
| 低动态 | 用可停留的分步状态保留变化关系，不因减少动画而跳过必需内容 |
| 图形/资源失败 | 暂停、保留对象与视点，重试或进入已验收同目标路径；明确能力缺口，恢复依[运行契约](runtime-contract.md) |

## 首个代表画面的放行条件

在本课目标视口实际查看进入态、操作中、回应后及阅读返回，按[真实验收](validation.md)保留证据。审阅者应能指认当前对象/关系、首动作和回应位置；同时检查长文本、缩放、手机键盘/触摸与深读后的焦点。

可用可见文字、常驻信息组和画面几何测量辅助比较前后变化，但这些数值不是通用质量分数。实际关注点、内容完整性和操作联系仍需审图与真实操作。[静态页面检查](../scripts/validate_page_structure.py)只核对基本语义与可读替代入口，不判断信息密度或沉浸品质。
