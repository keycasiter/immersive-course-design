# 交互、氛围与操作负担

以课程对象和学生行动建立设计。避免通用卡片堆叠、长表单和模板化文案；“去AI味”须落实为可观察的布局、材质、文案、动作与结果，不能只修改颜色。

## 先组织一次行动

视频主导课先按 `scene-participation-design.md` 推导对象、知识动作和交互表面，填写参与计划。直接场景控件、同对象深层阅读/实验和辅助卡按目标选择；卡片不作为全课默认工作面。一般课型沿用其自身交付配置。

- 一次只围绕一个当前问题或自然连贯的知识动作，保留一个主动作和必要辅助入口。不要同屏铺开全场所有选择、证据、解释、自检和提示。
- 单次判断通常保留2—3个简短、互斥且有诊断价值的选项。需保留不确定时用次要入口；若知识要求比较四个对象，可用紧凑的实物或对照，不为数量上限损害知识完整。
- 选项表达可比较的判断，不把一大段推理塞进每个按钮；选中后可展开原意或必要细节。不得改变答案含义，不能靠正确项更长、颜色或默认选择泄露答案。
- 原句取证采用可翻阅资料与点击摘录。保留完整原文、口径与引用位置，分段或分页阅读；不用跨资料长下拉菜单或默认展开全部引文。
- 整合解释和独立应用仍可包含完整要求，但按主张、依据、联系组织工作面，不制造无教学作用的点击。独立首答统一提交前不泄露反馈；草稿、已选依据、首答与修订分别保留。
- 提示、自检、口径和已存内容按需展开。删除重复标题、操作复述、泛化鼓励、技术过程和防御性文案。

## 让现场对象承载操作

按课程选择文书、仪器、标本、模型、路线、作品或其他现场对象。明确其位置、尺度、材质、排版和与人物的关系；不把所有内容都套进同一种悬浮卡片。

每个核心交互写出并实现“操作→状态改变→知识反馈→现场接续”。例如翻到下一段、夹入原句、标注差值、接通后观察输出、修订后交回记录。选中、未选、已存、缺项、错误、求助和修订状态均可辨认；hover效果只能补充，触摸和键盘必须能完成。

选取须在文书、教具或作品旁留下可辨认的记录，允许替换或撤回。单次点选即完成基础动作，拖拽只作可选增强，不增加必需确认与等待。多条依据显示最近一条与数量，其余按需查看，完整来源和撤回入口保持可访问。人物只确认取放时不能提前判正误；瞬时回应与持久化草稿分开，刷新不重播动作。

氛围由同一现场的构图、光线、材质、环境声、对象运动及角色参与形成。动态效果服务观察或反馈，暂停同步停止冲突动作，减少动态效果时保留信息与全部操作。遵循媒体与角色同场要求，不能把人物回应做成无实体的聊天提示。

页面背景随主视频变化，或入口需要对准移动对象时，必读[呈现、背景与锚点契约](video-presentation-contract.md)。按该 owner 区分体验氛围与教学内容，编译时间映射、对象轨迹和恢复行为，再接入运行模块与浏览器验收。

## 前端设计与验收

用 UICraft 沿用并补齐已有教学与设计上下文，用户指定 Prototype Craft 等工具时按其当前规范执行；按[前端与原型设计契约](frontend-prototype-contract.md)固定技术、tokens、运行时区域、状态和记录。按[课程成品UI与布局](final-page-ui-quality.md)选择适合对象、资料与操作的版式及所需完整能力。已授权浏览器验收时保存本版基线，完成结构与负担调整后再打磨表达，全课组装后复验。区域语义与教学规则保持一致，视觉比例和位置随内容调整；工具数量和动效数量不是质量指标。

| 准出项 | 必须实际检查的证据 |
|---|---|
| 情境设计 | 载体、排版、构图、材质、光向与本课对象一致；全课主要状态有统一设计 |
| 实际互动 | 点击/触摸/键盘使对象或记录发生可辨认变化，有对应反馈及现场接续 |
| 精简与可读 | 当前问题清楚，通常2—3个简短选项；必要例外有理由，资料可完整访问，长输入没有挤掉主动作 |
| 状态与恢复 | 未选、选中、缺项、错误、提示、修改与已存可辨；返回/刷新保留当前页、草稿和依据 |
| 同场与氛围 | 媒体、角色、对象与操作相接；有角色引导时实体参与，窄屏无真空对白 |
| 可操作性 | 桌面、手机和横屏的正文、底部动作、焦点、触摸区域与减少动态效果实测可用 |

在 `verification.md` 分列当前静态审阅、浏览器实测、正式媒体与真实试学。子工具只报告其实际完成的静态或运行证据；编排器按 scope、endpoint 和用户授权继续，不按工具名截断。实际浏览器验收记录截图、具体操作、结果与版本或哈希。长选项堆叠、核心交互只有装饰变化、主要控件不可操作或角色/媒体割裂，均先修复再准出。
