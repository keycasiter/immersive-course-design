# Video-led Surface Contract

本文件拥有 `video_led_web` 的学习者视觉状态；页面语义和运行时分别读取 `page-structure.md` 与 `video-led-web-course.md`。

## 硬门槛

`video_led_web` 是运行时布局契约，不是“页面里包含一个视频”的内容标签。实现必须先通过以下四项，再进入普通 UI 评审：

1. 播放态的唯一主内容是 `scene-media`；标题、目录、侧栏、证据卡、进度面板、结果卡、页脚和课程工作台不在首屏常驻。
2. 暂停态只打开一个与当前视频事件绑定的 `task-surface`；其它任务、历史记录和课程导航收起。
3. 反馈态只保留当前判断所需的反馈、帮助或修订；不增加独立结果页、并列卡片或长期仪表盘。
4. 返回态关闭工作面，恢复同一视频时间、字幕、对象、草稿和焦点。

任一项不成立，必须将页面降级为 `design_draft/static_design_prototype`，并在 `verification.md` 记录失败原因；不能用“页面可以打开”“视频已嵌入”或“交互内容完整”替代视觉门槛。

## 播放态

- 视频占据唯一主舞台，进入后隐藏课程大标题、常驻页眉、侧栏、目录与页脚。按媒体比例完整呈现关键内容；默认 `object-fit: contain`，安全区经验证后才可覆盖式裁切。
- 控制条与章节由触摸、指针或键盘按需呼出；保持可发现的播放/无障碍入口、键盘焦点和足够操作时间，隐藏控件不产生可聚焦的幽灵元素。
- 章节是按需导航，可在控制区域展开；选择后回到对应视频事件，不自动打开脱离场景的题目。
- 字幕按用户设置显示。人物首次介绍由实际视频承担，读取人物契约。
- 工作面关闭时不留题卡、框架标题、完成徽章或结果长文。确有行动的事件显示一个场景入口；不为观察镜头制造热点。
- `course-header` 只允许作为按需播放/字幕/静音/章节控件的语义容器；课程标题和课程导航不得借此常驻。
- `scene-objects` 只允许锚定当前画面对象的事件入口；不能承载全课目录、证据汇总或进度系统。

## 暂停与互动

进入学习互动先暂停媒体，再显示同一场景上的一个工作面；保留可辨认的人物、对象或资料锚点。窄屏可在暂停态将完整视频调整到阅读区上方，矮横屏可并排，返回播放态恢复整舞台。界面只要求当前一个判断，并显示完成它所需的材料和控件。首次进入的焦点与阅读起点落在当前问题，避免输入框自动滚动隐藏题干；重入按实际草稿恢复阅读位置。

工作面按知识动作选择：

| 动作 | 呈现 |
|---|---|
| 短判断、帮助、局部反馈 | 小型有界工作面 |
| 原文、对照、证据选取、理由 | 暂停画面中的阅读区，短材料贴近判断，较长材料按需展开 |
| 参数、测量、模型、仿真 | 当前对象旁直接控件或同对象深层视图 |

阅读区以正文、必要依据和一个主动作为层次。用长度和材料关系决定布局，保持可读字号；手机正文可纵向滚动，动作独立可达。原文标注与选择保留上下文；反馈指向具体原句、对象、关系或条件。视觉精简的同时保留推理深度，按 `instructional-design.md` 检查。

提交、错误、求助和修订仍停在同一事件；完成后收起工作面并回到视频。关闭未完成的必需互动只关闭表面，视频仍等待，并保留草稿与再次进入入口。回看与续学恢复精确时间、事件、草稿和焦点；不得留下旧任务覆盖新镜头。

背景重复热点/字幕在工作面打开时按需要隐藏，保留真正需要对照的画面材料。角色继续说话或引导时按媒体互动连续性保留同场锚点，不能仅剩姓名。

## 证据与边界

### 可选氛围层

`course-atmosphere` 位于视频下面，填充画面周围的留白；主视频、人物、对象、字幕和互动始终在上层。背景无声音、无输入、aria-hidden 且 inert，不能独有承载必需知识或推进课程。正常低幅动态、reduced-motion 静态与故障同场静态分别审阅；两种静态均失败时保留中性舞台。时间/状态/数据读取 `video-presentation-contract.md`。

视觉 Gate 允许 `visual_role=atmosphere`：填写体验目的、删除损失、attention_constraint 和实际资产/CSS/验收引用，明确 required_for_learning、covers_protected_content、receives_input、background_has_audio 全为 false。纯体验作用可不填写 teaching_purpose；学习作用仍需填写。逐态审阅是否抢注意或降低字幕/证据可读性，不能由层级声明直接推断像素质量。

`video_led_visual_gate` 使用 1.1。播放/返回主舞台只接受 `scene-media`，暂停接受同事件 `scene-media/task-surface`，反馈只接受 `task-surface`。暂停/反馈恰有一个主动作，播放/返回为零或一个；bool 不是数量。

`status=passed` 要求四态各自关联已存在的证据 ID，逐态覆盖 desktop/narrow，证据状态、course version、runtime fingerprints 和实际 artifact 路径/SHA256一致，并有实际采集时间。`runtime_file_snapshots` 逐项保存绑定证据标识、实际路径和 SHA256，独立 CLI 会读回这些运行文件。planned 模板只通过结构，不代表视觉验收。验证器机械阻断矛盾声明；截图中的布局质量仍需实际审阅。

真实视频使用 HTML video clock；分镜替代只声称实际实现的原型能力。CSS 模板提供布局起点，运行时实现状态、暂停和焦点；样式通过不等于浏览器通过。

本版浏览器证据至少覆盖：

1. 播放态视频占据舞台，控制条和章节能按需呼出并收起，键盘/触摸可操作；
2. 章节跳转更改正确视频事件，未出现脱离场景的题卡；
3. 打开互动时媒体暂停，仅显示当前材料、当前判断和主动作；
4. 正常、错误、帮助、修订、完成、关闭未完成任务和重新进入；
5. 返回、seek、刷新继续保留正确事件、草稿与焦点，旧表面已收起；
6. 桌面、手机竖横屏、长材料、缩放、字幕关闭和 reduced-motion 下可读，正文无横向溢出，动作不被遮挡；
7. 成片人物介绍和关键对象在 contain/经批准裁切下完整可见。

修改通用模板/CSS 后，运行[视频舞台回归](../scripts/check_video_surface.py)（需要 Python Playwright、Chromium 与 ffmpeg；已有 Chrome 可传 `--browser-channel chrome`）。脚本用隔离状态驱动检查桌面、手机竖横屏的舞台、按需控制、暂停阅读、初始问题、滚动和返回。实际课程的事件、字幕、恢复和学习验收继续按本版浏览器记录完成。
