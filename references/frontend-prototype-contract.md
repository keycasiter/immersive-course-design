# 课程前端与原型设计契约

按用户指定工具执行。新建与既有 Demo 迭代先区分；已有原型在原目录局部修改，共用课程外框，避免产生难以对齐的副本。

## 实现前固定设计

视频主导网页的编码、目录、运行时职责和交付等级以[视频主导课堂实现落地手册](implementation-playbook.md)为准。本文件负责页面契约和视觉/交互审阅，不允许另造课程时钟、事件状态机或独立恢复逻辑。

完成体验形态决策并确认网页交付适用后，按[课程成品UI与布局](final-page-ui-quality.md)复制[页面设计工作脚手架](../assets/page-design-contract.template.md)，将 Design Contract 保存为本课 `page-design.md` 后开始编码。该文件先标为 `design_draft`，最终契约须与本版页面和验收材料一同保存。记录：

- 技术与交付形态：用户指定技术优先；未指定时选择能完成本课操作的最简技术。实现必须先满足落地手册的运行时职责；纯静态示意可用 HTML/CSS/JavaScript，复杂组件、空间教具或媒体能力再选相应框架。引入框架不能改变视频时钟和事件注册表的唯一权威。
- 主题与 tokens：构图、材质、光线、主色、文字色、字体层级、间距、圆角和投影。使用中文系统字体或本地字体，离线原型不引入 CDN。界面图标统一，纯静态使用内联 Lucide；学科物件图示属于教具内容。
- 外框与页面：按 `experience_profile` 复用适用语义区域；不要求所有 profile 使用固定九区。按教学对象选择媒体舞台、直接控件、对象深层视图、资料/作品或必要辅助卡，并响应式重排。
- 视觉方向与阅读：写清主对象、资料载体、层级、阅读宽度、主动作位置、媒体裁切与手机变化；用真实题干、最长必要资料和字幕检查，不用空内容布局证明可读。
- 组件与状态：选取、翻页、引用、输入、撤回、缺项、错误、求助、已存与修订；给出点击、触摸、键盘和减少动态效果的实现路径。
- 内容与记录：统一资料来源，保存原始选项含义与精确引用位置；明确草稿、首答、受助与修订。纯本地操作不添加伪网络等待；需要模拟 API 时使用独立 stub，不连接真实模型、不伪造语义评分。
- 开篇与任务开放：按 opening 信息标识绑定实际正文、组件/字幕/镜头和呈现事件。课程定位与必要背景在每条入口分支首个学科任务前可获得；清空进度、独立小样、深链接、静音、媒体失败与恢复分别验证。继承背景失败时重新呈现必要信息；这不是必需媒体故障的降级路线。不以隐藏 DOM、标题或点击开始代表背景已呈现。

## 核心动作要有结果

把“取放”与“判断”分别实现。点供给物后在收货单留下记录，点原句后夹入批注或作品旁；再次选择或通过次要入口可撤回。撤回后恢复空状态和必填检查，不覆盖已保留的尝试。

一次点选即可完成基础动作，不为氛围增加必需拖拽、二次确认或连续动画等待。多条依据保留顺序，最近一条可见，其余按需展开；原文、来源与取下操作始终可访问。替换 DOM 后保留正文阅读位置，并把焦点放回原句、可用控件或当前问题。

让同场人物以指向、接物、翻页或交回回应。回应只确认取放时，不说知识结论；错误与解释反馈由课程规则或实际审阅触发。回应随实体定位并避开脸、工作面和主动作，换屏后重算；切换工作面清除过期回应，刷新不重播瞬时动作。首次介绍的时长读取项目配置或单课覆盖，与回应分别管理。

## 工具阶段与验收证据

使用 Prototype Craft 时先读其当前 Skill。输入为已确认设计或明确示意范围、界面契约、资源和状态；输出为代码、依赖清单、prototype_built、static_reviewed、未执行项。它的静态结束条件只适用于子工具阶段。

子工具返回后由本课程编排器接回：完整小样或实现请求已有浏览器验收授权时继续启动、操作和验收；只要静态示意时按范围结束。用户授权优先，不因子工具终点新增确认。文件交付、运行可用、媒体接受和真实试学分别记录。

静态审阅交叉核对文件和锚点、固定层级、唯一标识、事件绑定、变量/空值、引用合法性、首答锁定、焦点回退、离线资源与响应式规则。没有运行的操作不能记为“实测通过”。

在已授权的浏览器验收范围内，按课程 Skill 检查全主线、错误、求助、修订、恢复、桌面、手机和横屏。功能可运行后进行 UICraft 成品打磨，核对布局、中文排版、自然文案、缩放、焦点及边界；全课组装后用正式媒体复验。验证记录分列“本次静态审阅”“本次浏览器实测”“本次设计审阅”“正式媒体”“真实试学”；截图与操作轨迹绑定本版入口、状态、视口和版本/哈希，旧结果不作为最新交互已通过的证据。

视频主导网页运行 `scripts/validate_video_led_runtime.py <event-map.json> <index.html> <runtime-source.ts-or-js>`，按事件图的 `runtime_mode` 派发：

- `video_clock`：真实 `<video>` 时钟驱动事件，执行播放、seek、字幕同步和返回检查。video_led_web的正式运行只接受此模式。
- `storyboard_events`：仅用于完整非视频 Demo；事件图 schema 1.2，稳定 Beat 顺序和已验收分镜承担事件推进，单一状态存储实现暂停工作面、关闭保留草稿并阻断必需任务、完成返回同一事件、回看和刷新恢复。读取 `assets/storyboard-event-map.template.json`、`storyboard-runtime.template.js` 与 `storyboard-demo.template.html`；填入真实内容后执行所有非视频路径和四态视觉门。可用 HTTP 本地服务进行浏览器测试，框架构建按项目真实命令执行。

原生空间/混合路线使用`scene_state`和[场景计划](spatial-learning-contract.md)，按其入口/源码/知识矩阵/浏览器指纹与正式运行路径验收；不能把分镜载体改标签冒充正式3D。

分镜检查明确报告真实播放/seek/字幕时序尚未验证；纯静态分镜不满足事件载体。正式视频接入使用独立 `runtime_delivery`、新浏览器记录和媒体回归，保留已确认的 `demo_runtime` 及其证据。结构检查和文件哈希只检查关联，实际操作仍须浏览器证据。

维护分镜载体模板后运行 `scripts/check_storyboard_runtime.py --browser-channel chrome`（或已安装 Chromium 默认通道）；它实测桌面和手机竖横屏的暂停、关闭阻断、草稿、反馈返回与刷新恢复。通用载体测试不替具体课程的全路径浏览器验收。

纯HTML用 validate_page_structure.py --mode static_markup。组件应用构建并在浏览器运行后保存 document.documentElement.outerHTML 与JSON采集记录（url、captured_at、browser、application_version、viewport、dom_sha256），再用 --mode runtime_dom --runtime-evidence 校验真实DOM。采集记录证明对象与哈希关联，不自动证明页面可操作或控件可访问；这些仍需实测。
