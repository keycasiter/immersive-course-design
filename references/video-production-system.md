# 通用视频生产系统

所有新课程视频与重大视频改稿默认执行本模块。它将参考研究、声音、分镜、TRAE `GenerateVideo` 生成任务和时间线连接起来；不是某一课的提示词。工具默认值读取[项目生产配置](project-production-profile.md)，实际调用及恢复读取[媒体任务运行与恢复](media-job-execution.md)。

## 1. 建立本次生产环境

复制 `assets/video-production-environment.template.json`，保存为课程目录的 `video-production-environment.json`。不得用第三方 Skill 写出的模型名称、参考语法、时长或分辨率证明当前工具支持这些能力。

逐个实际提供方登记：

- 提供方与工具标识、接口/工具版本、实际可知模型；没有返回模型时写 unknown。
- 输入方式：文字、图片、首/尾帧、视频、声音身份、声音时序、音频驱动口型、多镜头、前/后延伸、局部编辑。
- 每项能力分别记 verified / unsupported / unknown。verified 保存官方契约或本次成功请求及实际输出证据；关键质量另外验收。
- 可提交的连续范围或离散时长、画幅、分辨率、帧率、输入数量与尺寸限制。来源时长、计划时长、可提交档位、实际返回时长分列。
- 原生声音、固定声线、配音驱动口型、字幕、角标/水印与正式交付限制。
- 权限、计费授权、重试/预算、通知或查询策略、共享 GPU、磁盘与回传路径。凭证和私有端点留在本地连接配置。

先检查可用性，再选择路线。unsupported 不重复试；unknown 只允许在授权内做能力小样，不能批量依赖。换工具或模型后，重算受影响的声音、单元边界、参考槽位与输出规格，不只换模型名。

TRAE `GenerateVideo` 目前可提交什么以本轮工具说明和[已验证行为](video-generation.md)为准。本地声音默认 Qwen3-TTS 固定参考。Wan、Seedance 或其他视频后端不属于本项目正式生成路径，除非用户明确更新项目配置并重新完成能力小样。借鉴 Flova 方法不代表安装或接入 Flova 服务。

verified 能力的 `evidence` 为 `{"path":"实际证据文件","content_sha256":"实际SHA256"}` 数组；证据文件说明版本、输入约定、请求/输出和核对结果。单元 `reference_bindings` 使用 `reference_identifier`、真实 `slot` 与 `purpose`。例如 voice 职责须实传固定源声并要求已验证 voice_reference，不能只登记一个未送入工具的声线文件。

## 2. 输入研究与参考包

存在提供或继承的图片、音频、视频时，先执行[输入媒体实检](source-media-admission.md)。源内容观察与模型参考槽位分别留证，输入失败阻断依赖该源的制作路线。

人物参与时先执行[人物参考与首次出场契约](character-reference-and-introduction.md)。查找并登记人物/情境来源，再定义外观与固定识别点；缺少合适参考时记录查找结果和自由补全理由。研究记录与实际送入模型的参考文件分别保存。

先区分来源事实、教学情境和视觉创作。已有视频按真实切镜逐 shot 记录来源时间、动作、对白、视线、道具和转场；不受生成模型上限影响而漏分析。已有图像拆出构图、色场、材质、光源、空间、身份与用途，写出要继承和要排除的因素。

建立稳定实体与文件绑定：

| 实体/参考 | 应保留的信息 | 使用边界 |
|---|---|---|
| 角色 | 脸部识别点、体态、发型、服装层、固定饰品、声线与状态变体 | 各角色继承共通风格，保持各自身份；不复制同一张脸 |
| 场景 | 空间地图、地标、入口、前中后景、尺度、光向与时间 | 场景总览不等于最终机位；同场多个机位从同一空间推导 |
| 道具/教具 | 外观、结构依据、数量、尺寸、持有者、接触点与状态 | 精确结构及教学结果由确定规则核对，模型不得自行决定 |
| 声音 | 干净单人源声、完整参考文本、SHA256、身份与试听结论 | identity、timing、soundtrack 用途分别核实；不能互相替代 |
| 分镜审阅板 | 每格是独立镜头还是同镜时刻，人物/相机分别运动 | 带箭头、格线、文字的审阅板不可直接当正式首帧 |
| 正式首尾帧 | 实际机位、主体、光线、动作状态与纯画面 | 使用正确单格或重新构图；不把整张参考板塞进首帧 |

按实际风险补正/侧/背面、表情、手部动作、服装或道具细节，没有固定图数或九宫格要求。裁切和拆图优先确定性工具；缺失的背面、结构和被遮挡区域标创作补全，不冒充原图事实。

写实主参考使用摄影级材质、肤质、光线和环境；Blender 只作空间或机构校验，除非已确认 CG 风格。准确文字、数字、图表、公式、软件 UI 与真实规则交给确定性叠加或运行时录制。

## 3. 以实际声音确定时间

先定完整脚本及说话人，再选：

1. **固定配音驱动表演**：先生成/录制并听审最终角色人声，以实际文件确定时序，再由支持的音频驱动口型能力生成说话画面。
2. **固定声音参考的原生有声表演**：先验证声音参考确实约束身份，再让画面与对白同期生成。返回后以实际台词和声音重测时间，不把请求秒数当台词时长。
3. **旁白/同场画外声**：固定人声可先生成，再按信息揭示、对象操作和听觉事件规划画面覆盖；不用闭嘴人物伪装画内对白。
4. **原生新声候选**：可用于声线发现和同源试验；保存真实源声、台词及声音身份。未证明可稳定扩展整课前，不能替代已确认角色声库。

字数/语速只作早期估计；正式计划以实际录音、逐句听审和校对过的时序为准。不得截句、吞尾字、加速人声或缩短教学停顿迁就固定镜头。声音过长时补有教学作用的行动/反应/对象镜头，重新拆分自然话轮，或使用已验证的延伸能力。

声音事件同时记录最终时间线绝对时间和生成单元相对时间。每条完整台词保留 speaker、正文、声线参考、音源、源文件截取区间、停顿、实际发声区间与对应视觉事件。VAD/静音检测用于找候选边界，不能把呼吸、轻声、术语尾音或正常停顿自动认定为台词结束。

## 4. 从实际分镜编译生成单元

复制 `assets/video-production-plan.template.json`，新计划使用 1.2，继承 1.1 人物契约。逐场覆盖主线和必需反馈/求助/返回，保留学习目标与资产标识。登记 `character_sources`、`characters`、每镜人物与 `character_introductions`；无人物计划显式保留空数组。字段和首次出场规则只由人物契约拥有。

**shot** 是实际剪辑中的连续镜头；**generation_unit** 是一次独立生成请求。两者不强制一对一：

- 同场、同时间、状态连续的 shots，只有提供方已验证支持多切镜时才合成一个单元。
- 一个长 shot 超过能力上限，保留原分析，另写生产分段、源区间和无重复的接续。
- 拆在完整话轮、动作完成、反应或自然切点；不在字词、关键接触或证据揭示中间切。
- 短镜对应提供方更长档位时，规划有意义的前后余量并登记实际选取区间。
- 一个单元输出被多个 shots 引用，时间线只装配对应源区间一次；不能逐 shot 重复拼整段。
- 同一输出的重复源区间仅在明确回看/教学重播时复用，登记目的；不拿循环补旁白缺口。

每个单元保留：教学作用、首尾状态、角色/场景/道具、shots、声音事件、所需能力、提供方、可提交时长、参考文件槽位、提示词版本、任务记录与候选产物。模型变化时重编译这些字段。

1.2 的 `submission_expectations` 保存本次适配器、实际可知 model、parameters 和 output_contract；完整 prompt 与 reference_bindings 继续使用已有字段。台词事件引用 `utterance_identifier`，计划绑定真实 `utterance_registry_file/sha256`。实际输出引用 `output_attempt_identifier`；Job 中的完整读回与指纹由[媒体任务运行](media-job-execution.md)单独定义。相邻及跨分支接缝由[导演连续性](video-direction-and-continuity.md)和[实际时间线](video-timeline-and-quality.md)定义，不在单元里复制另一套台词或终态权威。

## 5. 导演、表演与提示词编译

执行[导演与连续性](video-direction-and-continuity.md)。提示词从结构化单元编译，按当前 API 的真实字段输出：

`用途与主体 → 场景/参考职责 → 起始状态 → 按顺序的动作及声音 → 机位/运动 → 光线/材质 → 终止与接续状态 → 必要限制`

具体写：

- 观众此刻看什么、为什么；相机位置/高度/方向与人物/物体运动分别描述。
- 一个主要行动链；单 shot 默认一个主要相机运动。能力允许的多 shot 单元逐镜按顺序写，不能把“每镜一个运动”误解为全单元只有一个静态动作。
- 真实说话者、完整对白、说话前倾听与说话后反应；声音身份和本场表现分开。
- 参考数组顺序与实际文件对应，注明 identity / scene / prop / first_frame / last_frame / voice / timing / previous_clip 的用途。文档中的实体 ID 不等于工具输入绑定。
- 工具支持时间码时传相对时序；不支持时用有序动作、完整台词与可提交时长表达，精确事件留在剪辑契约中。
- 台词与表演指令按提供方字段拆分；不把某个后端的英文标签、`@Image` 或音频参数直接套给 Qwen/TRAE。

编译时核对参考冲突、单元时长、话轮完整、角色数、未验证能力、手机可见性、准确教具与角标限制。真正提交前必须读取并执行[提交读回关口](media-job-execution.md)，比对最终参数文件与当前计划；完成本段设计检查不替代该关口。靠“电影感、8K、完美口型”文字不能证明质量或接口能力。

## 6. 生成、修复与全量组装

先按原来的两道确认门完成最难媒体闭环；声音时长覆盖、固定声线、画内口型、主要接缝、窄屏与互动恢复均作为关键风险。无需新增逐图/逐镜人类审批。

每次生成按 job 保存请求指纹、任务 ID、真实参考、参数、候选版本、文件 SHA256、成本与错误。已生成只续取；质量失败定位输入研究、实体参考、表演、单元边界或后期中的具体层。

先查实际参考是否漏绑、错序或与当前视角不兼容，再定位身份、地图/机位、接触阶段或光源问题。实际依赖前片的任务，等待其采用区间、边界状态、参考文件和版本核验完成；独立任务无需等待。局部修订保留已验收且不受影响的资产，沿真实前驱/后继更新提示、绑定、声音与接缝证据。运镜失败时可在已确认教学目的内简化机位/运动；关键教学作用变化按原确认契约处理。局部编辑、前/后延伸、前片引用仅在能力已验证时使用。

后期及完整准出执行[时间线、声音与实际验收](video-timeline-and-quality.md)。按人物契约确定性排字并烘焙首次出场姓名/身份，复查实际人物人数、外观、介绍和手机安全区，保存绑定最终成片的审阅。生产清单继续记录资产治理和确认；视频计划补充真实时序与生成契约，两者不能相互替代。

## 7. 运行关口

生成前：

```bash
python3 "<skill-root>/scripts/validate_video_production.py" \
  "<course-directory>/video-production-plan.json" \
  --manifest "<course-directory>/production-manifest.json" \
  --blueprint "<course-directory>/course-blueprint.json"
```

每次新请求形成实际参数和 Job 读回后，在同一命令追加 `--pre-submit --unit "<unit_identifier>" --report "<course-directory>/submission-validation.json"`。一次只检查一个未提交单元，使用通过检查的同一参数快照调用；已经提交的任务进入恢复分支。

成片后在计划命令追加 `--delivery --report "<course-directory>/video-validation.json"`，不与 `--pre-submit` 混用。计划检查允许估计时序；提交前检查验证真实请求；交付检查验证采用 attempt、输出文件、源 PTS 接缝和本版质量证据。这三种报告分别成立。

输入实检与复用恢复前检查执行各自 owner 的独立命令。成片 `--delivery` 遇到单元 `asset_reuse_file` 的新采用路径时自动核对 materialized 身份；它不代替输入实检或复用前检查。报告分别登记在媒体计划与验证记录中。

新课含视频时，上述检查与课程/生产联合检查一起运行；非视频课不生成空视频计划。旧课不自动迁移，新规则只在授权的视频改稿范围落地。1.0 报告提示人物未校验，1.0/1.1 均提示最终请求与源 PTS 接缝未校验；不能以旧通过报告声称 1.2 全项通过。方法来源及覆盖深度见[Flova 方法采纳索引](flova-video-methods.md)。

输入实检、已选资产复用与确定性视听对齐的来源和修正见[OpenMontage 采纳索引](openmontage-methods.md)，执行规则仍读取各 owner。
