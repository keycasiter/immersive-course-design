# Skill维护

维护范围是方法、配置、模板与脚本；不自动创建课程或调用媒体生成服务。使用skill-creator与writing-for-agents组织触发、职责归属和按需读取。

## 先核对再改

核对启用目录、checkout、远端基线及现有调用者；先列“确定结论 / 证据路径 / 不确定项 / 改动范围”。反馈应转成跨题材方法，课程人物、画风、参数和迭代截图留在课程工程。

| 内容 | 维护位置 |
|---|---|
| 任务定位、阶段地图、共通约定 | `SKILL.md` |
| 实施顺序、每阶段输入/操作/产物/收口、局部修改接续 | `production-workflow.md` |
| 设计、空间交接、运行、声音、页面与验收方法 | 对应专题参考；与阶段流程互相引用，避免另写一套阶段定义 |
| schema、真实字段和状态/指纹 | 场景契约、生产与版本、运行契约；字段先归合同，再改模板/脚本/正反例 |
| 填法和接口应用 | `worked-example.md`与关联例子；示例不冒充已验收课程 |

当前2.0只保留体验驱动路线，旧合同在Git历史保存，旧包不自动迁移。删除资源前核对调用者；保留未受影响资产/声线，不从过往失败继续堆叠通用禁令。

## 验证与同步

修改脚本运行真实正反例及相关回归；文档检查相对链接、锚点、路由可达性、归属与冲突。涉及示例时实际验证/编译及执行关联测试；复杂指令可在授权时以独立Agent执行不同题材与局部修复任务，记录实际行为而非只让它评价文案。

方法测试不证明真实课程画质、互动、人工确认或学习者效果。核对当前安装无并发改动后，备份并同步；按[同步约定](../AGENTS.md)正常提交/push、回读远端SHA，报告实际改动、验证与边界。
