# Skill 维护与 Agent 接续

当用户要求优化本 Skill、Agent 行为、模板或验证器时，先进入此分支。使用 writing-for-agents 的触发指针、渐进披露、单一归属和逐步完成条件；实际目标是当前会话启用的 Skill 路径。

先从当前要求和既有授权区分仅审查与授权维护。仅审查按以下步骤定位、追踪与验证问题，交付文件位置、复现证据和建议；授权维护则原位修复并完成全部相关回归。两条路线都在完成本分支后交付，后续课程流程只由单独的课程任务触发。

## 执行

1. **定位**：确认实际启用目录和已有同名副本。原位更新已授权的目标；多个候选无法区分时再澄清。完成条件是唯一目标可读、修改范围明确。
2. **归纳**：把反馈写成“触发条件 → 期望行为 → 可观察失败”。剥离案例名称、人物、题数、颜色、镜头顺序与固定场景。完成条件是每条规则可在不同课程复用。
3. **归属**：查[契约归属表](contract-ownership.md)，在一个 owner 中定义含义、字段和边界；主入口只保留到它的强触发指针。完成条件是每条变化有唯一权威来源。
4. **接通**：追踪 Agent 从派发、设计、生成、后期到验收实际会读什么。同步模板、运行接口与可机械检查项；语义质量保留实际审阅责任。完成条件是强制规则不只藏在文案或页面文件。
   路由性能或交付收敛改动还须按 `execution-flow.md` 核对：当前阶段先写实际内容，后继生产材料按触发加载；首份快照、完整交付与验收分别计数。实测用原输入与时限独立重跑，提示/模型/条件变化单列，续跑不计首轮成功。
5. **回归**：为改变的契约运行有效正例和典型失败反例，包括空/缺失、引用错、版本兼容和旧证据。执行所有修改脚本及相邻既有回归；模板仅做语法检查。完成条件是错误能被阻断，合法路线仍能通过。
6. **交付**：核对 frontmatter、相对链接、JSON、实际生效目录与本轮脚本结果。报告改动及仍需实际课程/人类检验的边界。完成条件是可直接使用的 Skill 已落盘。

维护任务不创建单课 blueprint/manifest，不生成具体课程媒体，不替课程签确认。若用户同时要求修案例，分别记录授权范围并复用通用规则实施。

## 修改影响

| 改变 | 需要复查 |
|---|---|
| 触发与路由 | 对应分支能直达 owner，未触发分支不加载其全文 |
| 字段或必需规则 | owner、模板、校验器、报告版本、正负用例 |
| 页面呈现 | 播放/暂停/反馈/返回状态，真实浏览器桌面与窄屏 |
| 教学任务 | 目标深度、依据、反馈、撤架、独立应用 |
| 人物或视频契约 | 来源、出镜覆盖、首次介绍、实际成片与绑定指纹的审阅 |

局部修订先记录保留项、改变项、补全项及真实引用它们的后继。改正文重查权威台词、实际请求、声音/口型/字幕及对应任务；换参考重查用途/槽位/视角与输出；改采用区间重查 PTS 接缝、事件时序和当前成片审阅；只换音乐先检查重混范围。未受影响的已验收资产保留，最终交付实际替换文件或正文。

既有课程只在授权改稿范围迁移；新模板使用新版本。旧版仍可读取时明确列出未校验的新契约，不能把旧通过结果称作新版全项通过。

Skill 更新不另设课程人类确认门。课程改稿影响原确认范围时沿用 `orchestration-and-status.md` 的设计/代表性闭环确认、独立澄清/Demo 门禁与失效规则。
