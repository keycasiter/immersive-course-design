# 分镜独立审阅与案例评测

创建或修改教学分镜、单独 review 分镜，或用案例优化分镜规则时读取。分镜文本可单独交付诊断；当前范围不创建课程 blueprint/manifest，不进入 Demo、媒体生产或课程确认流程。

剧情、角色、行动和镜头语义仍由 [剧情—教学—分镜](narrative-storyboard-integration.md)拥有；本文件拥有审阅步骤、局部记录及案例比较边界。源文件的互动信息与揭示按 [故事板与交互状态](storyboard-and-interaction-spec.md)，独立评价按 [课程评价](course-evaluation.md)执行。

涉及教学方式的生成或评审，先读[学科教学与体验选择](subject-pedagogy.md)及适用知识类型。生成时先作教法选择再编镜头；评审时按原正文检查难点、表征、体验关键时刻和撤架是否匹配。结论引用具体材料与动作，记入对应问题和观察，不新增评分维度或通过阈值。

## 逐步审阅

1. **固定正文**：保存实际动作、逐句对白/明确无声、材料、输入、反馈和返回；保留镜头标识。记录文件 SHA256、全部或选中范围和未读范围。完成条件是审阅对象能按当前字节复原，不只有目标表或质量说明。
2. **只读分镜**：移开作者的目标表、质量标签和解释，沿正文审进入、行动来由、角色/系统响应、换材料、返回及收尾。之后回读体验承诺，核对承诺与执行的差别。自审如实记为 `author_self_review`；减少解释输入不等于消除作者记忆。完成条件是每项发现或成立判断都引用实际位置。
3. **走两种输入**：对承诺会改变对象、记录或后续的互动，按 narrative owner 的“承诺核对”走两种输入到下一镜和返回。没有这类承诺时说明线性观察/示范的实际参与；不为表格硬造分支。完成条件是能从正文定位差异与汇合，或明确记录缺失。
4. **覆盖与边界**：每个已选镜头和其正文包含的错误、帮助、未答、修订、返回均实际读完。逐项记录下方维度；无角色等条件性项写理由，媒体/真实节奏/学习者结果保持未评。完成条件是已读范围与报告声明一致，局部文本审阅不升级为正式沉浸验收。
5. **修订复测**：保存旧记录与正文；修改受影响的动作、对白、材料或响应，再以同范围和维度重读。变更范围扩展时单列；实际文件变化使旧绑定失效。完成条件是每项修复有新正文证据，残留和未评项仍可见。

## 文本维度

| 维度 | 阅读对象与 owner 边界 |
|---|---|
| `opening` | 当前对象、未完成事务/观察与进入；安静或明确教学入口也可成立 |
| `causality` | 行动前的需求/条件、行动后变化及学习作用；见 narrative owner |
| `participation_promise` | 被承诺的影响与真实输入差异；见 narrative owner 的承诺核对 |
| `character_strategy` | 人物资源、尝试、回应；系统/无角色路线可不适用 |
| `material_transition` | 新材料/新尺度来源、出现时机和带回结果；见 narrative owner |
| `evidence_boundary` | 事实、合成材料、模型、推断及未知；见相应学科与来源 owner |
| `independent_release` | 示范/引导/独立、首答、帮助与反馈揭示；见 course-evaluation |
| `branch_return` | 当前对象、输入、辅助、首答与分支差异的返回/汇合；见 narrative owner |
| `closure` | 实际作品、解释或状态怎样兑现当前承诺；理解判断仍需相应证据 |
| `presentation_budget` | 图字与声音任务、停顿、读数和操作的预演条件；文本不能证明实测时长 |

这是局部分镜诊断目录，不为 M13/M18 增设评分或合格线。每项为 `present_in_text`、`issue`、`not_assessed` 或 `not_applicable`；前者只表示正文有支持性设计，不表示实际体验通过。

## 审阅记录 1.0

机器字段与枚举由 [storyboard-review.contract.json](../assets/storyboard-review.contract.json)拥有；从 [记录模板](../assets/storyboard-review.template.json)填实际记录：

- `source` 引用审阅根目录内的实际 UTF-8 文件和当前 SHA256；`scope.units` 用稳定标识与行区间界定已选分镜正文，`whole_storyboard` 覆盖所有非空正文，`selected_units` 如实限定范围。
- `reviewed_unit_identifiers` 只填已实际读完的单位。每项维度登记适用状态、所读单位、原句及行区间、观察；问题/成立判断要有正文证据，未评/不适用也写具体理由。
- `participation_checks` 保存两种输入的实际差异、下一单位与返回状态以及审阅观察；它是文本走查记录，不是假造 UI 操作。如果未承诺响应，填写 `participation_check_not_applicable_reason`。
- `review_kind`、`reviewer` 与 `limitations` 记录真实作者关系和能力范围。`semantic_acceptance` 固定 `not_computed`，`media_evaluation` 与 `learner_evaluation` 固定 `not_run`。正式媒体或学习者证据使用各自 owner，不能塞入文本记录冒充验收。

运行：

```bash
python scripts/validate_storyboard_review.py --review <记录.json> --root <正文根目录>
```

退出0仅表示记录、当前绑定、声明范围和引语位置一致。脚本不判断引语是否支持观察、剧情是否吸引、两种输入是否有有效教学差异，也不认定作者身份。保留实际审阅责任；合法记录中可以包含严重设计问题。

已有设计不因缺新 sidecar 自动失效。新建/修订分镜记录使用1.0；旧设计 review 时生成当前范围记录，不能把旧结构检查说成已执行本项。

## 多案例维护

先固定样本角色：自然初稿、植错反例、合法对照及迁移检查分别计数。覆盖不同学科、人物/无人物、整体/局部、线性/响应与示范/独立任务。具体名字、台词、固定镜头数留在案例目录。

先收正文证据，再把失败归纳为“触发 → 应有行为 → 可观察差异”；只修改通用 owner、路由、模板和可机械检查项。修稿对照与新案例分开报告；作者知道规则的迁移样本不称为盲测。要主张 Agent 行为改善，另外执行同输入、同模型/工具/时限的独立重跑，原轨迹与未完成结果原样保留。文本自审不能证明实际沉浸或学习效果提升。

使用外部课程库扩充案例时先读[外部课件参考库](external-courseware-reference-library.md)，按实际观察层级登记：`catalog_only` 只读到标题/封面，`description_observed` 读到公开说明，`runtime_observed` 实际运行并记录状态。前两级可支持题材、命名和声称用途，不能支持交互、叙事、反馈或学习效果判断。浏览量、点赞、精选、热门及标题中的“沉浸/3D/漫游/实验/AI”均不是质量证据。

从外部作品提取的是体验族与风险条件，不复制具体角色、台词、镜头、资产或玩法。多案例覆盖观察、创作、仿真、程序操作、社会决策与程序性技能等不同知识动作；合法线性示范和无人物路线保留为对照，防止规则只奖励强剧情和显眼分支。
