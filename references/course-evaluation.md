# 贯穿设计与试学的课程评价

评价从目标定义开始，随开场、讲解、任务、媒体和反馈编排持续更新。将评价标准与实际材料写入设计及 `evaluation-plan.md`，不能等成品完成后再补一套试题。

新课、重大体验改稿、沉浸评审或实际体验效果声明，必读并执行[沉浸设计取证与体验评价](immersion-evaluation.md)。在设计阶段建立意图映射，审阅阶段保存本版逐实例证据，试学阶段分构念测量；完整旅程与背景增量另评。该 owner 拥有 v2 plan/packet 与校验，教学量规仍由本文件负责。工程通过、体验评审、学生感受和学习表现分别报告。

## 先明确教学核心与成功标准

1. 用一句话写“学完能自己完成什么”，保留来源要求的必需范围。
2. 为每个目标写可观察的动作、成功标准、预期困难、所需依据和适用范围。
3. 先确定新情境的独立任务，再反推需要的讲解、示范、练习与反馈。
4. 按阶段提供帮助并逐步撤除。没有讲解支撑的自由探索不能替代教学。
5. 开场先解决背景与动机；开场理解、课程完成、知识掌握分别评价。

按学科选择证据：数量看结果、单位与推理；机制看预测、规则与解释；历史看事实、证据、因果及范围；语言看语境与表达；技能和创作看过程、约束与作品。不要为所有课程套同一评分表。

## 形成性评价必须改变下一步教学

按 Black 与 Wiliam 的形成性评价定义，证据要被取得、解释并用于下一教学决定。显示正误或收集日志只完成其中一部分。下列实现方法是对理论与反馈综述的转化，依据见[学习科学依据](learning-science-evidence.md)的 LS6。

在重要练习节点写：

| 取证 | 解释 | 教学动作 | 再检查 |
|---|---|---|---|
| 实际题干、答案、依据或操作结果 | 对照成功标准，列可能缺口和替代原因 | 给哪个说明、示范、对比或操作支持；学习者具体修订什么 | 用哪项实际任务检查缺口是否改善，怎样区分受助和独立 |

优先选择能区分主要困难的证据。选择题中的干扰项应对应有依据的错误推理，但一次选错只是假设，不能当成误解诊断已成立。证据不足时追问关键理由、给可核对的短任务或交给审阅；不让 AI 用流畅解释填补缺失证据。

常见分支：

- 结果正确、理由缺失或矛盾：查关系与条件，不直接判掌握。
- 结果错误、方法成立但计算或表达出错：定位执行环节，不重讲全部概念。
- 规则被用于不适用条件：提供对比或边界例，再让学生自己选择与解释。
- 控件、语言或资料可达性障碍：提供同目标支持，区分障碍与知识不足。
- 尚未作答或证据无法解释：保留待判断状态，提供求助或补充取证。

本题修订属于闭环内再做；后续独立新任务用于检查帮助撤除后表现，两者分别记录。若许多学习者在同一关系出错，外层动作应是修改讲解、示范或材料，而不是增加每人的提示次数。自动分支不要求复杂自适应模型，明确规则和人工待审入口即可。

反馈针对任务与可改动作，兼顾时机、注意力和学习者基础；不以夸奖、扣分或把答案自动填入替代修订。不规定即时或延时反馈永远更好，独立评价先保留首答以避免污染。

例如，给定路程随时间的两点 `(2秒, 6米)`、`(5秒, 15米)`，学生答“9米／秒”。先保存答案并请其指出使用了哪两个变化量；这个结果可能来自只求路程差，也可能是单位书写错误，不能直接定诊断。若其把9米当作速度，示范3秒内的路程变化并让其自己完成比值；再用 `(1秒, 4米)`、`(3秒, 12米)` 检查能否得到并解释4米／秒。再查结果属于接受过反馈后的新材料表现，不追认原首答。此例为设计示例，未执行学习效果研究。

## 每处互动都审视价值

将互动用途明确为 `core_reasoning`（核心推理）、`evidence_collection`（取证）、`orientation`（情境引导）、`operation_support`（操作支持）或 `independent_assessment`（独立评价）。

| 检查 | 必须回答 |
|---|---|
| 目标或支持作用 | 支持哪项目标或哪项必要的理解、引导、操作？ |
| 学生思考 | 必须自己完成哪步观察、比较、预测、解释、表达或修订？ |
| 预期困难 | 哪种误解、解释不足或操作困难会产生不同表现？ |
| 学习证据 | 哪个答案、作品、依据、关系或修订能支持判断？ |
| 反馈作用 | 怎样定位具体缺口，之后让学习者实际再做？ |
| 删除损失 | 去掉或简化它会失去什么？ |
| 注意力成本 | 是否让阅读、找物、控件或次要知识挤占核心思考？ |

辅助互动可有意义，不要求每次翻页和领路都变成测验；明确其辅助作用，不计为掌握。主线时间和制作投入优先保证核心思考与独立应用。没有新增知识动作的重复任务可合并，超出必需目标的细节可列拓展。

检查任务是否可以靠按钮措辞、答案高亮、位置、抄原句或反复试点通过。反馈需要随实际误解改变；所有选项得到同一回答不能提供有效诊断。若学生能正确解释却受控件阻碍，先解决操作问题。

## 对准同一能力设计新任务

变化数据、对象、材料、约束或条件，保持能力标准可比。仅换名字、地名或按钮位置不能充分检查迁移。根据学科安排必要中间关系、相近概念辨别、变化后的预测、证据不足判断或新作品。

检查前不预填正确解释，不把答案与明显荒唐的选项并排。开放任务允许多种合理表达，写清必要评价要点与例子；语义自动评分未经验证时，使用人工审阅或可靠结构化检查，不以关键词替代理解。

首次答案、使用提示、看到反馈后的修订、后续新任务分别保存。此前正常教学不算当前新任务求助；看到当前题或该目标答案解释后再答不能记为首次独立。关联任务使用下面的整组释放合同，不能在单题提交后开放能提示未答任务的解释。

## 评价完整性合同

新建或修订独立评价／迁移任务时，生成 `assessment-integrity.json`，模板为 [assessment-integrity.template.json](../assets/assessment-integrity.template.json)。本节拥有首答、帮助、释放及结果类型；迁移变化含义由 instructional-design.md 拥有。旧课不自动追溯迁移，未执行该合同的旧通过记录不能称新版全项通过；blueprint/manifest 既有 schema 保持兼容。

1. 先把可能相互泄露答案的任务按共享知识或解释分组，记录全部 `first_response_items`。无关联任务可单独成组，组数和题数随本课决定。
2. 学生可逐项编辑和保存，只显示非答案性保存状态。整组每个必需答项的首答、显式不确定或跳过记录均已持久化，才开放该组的答案、正误、答案性量规、提示、高亮及旧解答。未答保留 missing evidence，不自动计作正确独立表现。
3. 首答阶段允许原材料、无障碍等价信息及纯操作帮助。知识求助先持久化已答／未答和受助状态，再开放帮助；整组记受助，后续答案不追认原独立表现。允许资源按目标声明，不把所有工具或正常教学算求助。
4. 关闭、刷新、重开、历史路由、深链及清空后的继续都重建同一释放状态与知识暴露历史。缺失、损坏、版本不符或保存失败时保持锁定；不能由内存标记、导航或删除数据消除已见答案的事实。
5. 开放解释未经校准保持 `review_pending`；自动规则只判已声明的确定性输入。自评与关键词命中不能升级掌握。修订、`post_feedback_recheck` 和原独立首答分开，后继新材料改善不倒填原首答。

合同字段：

| 字段 | 必需内容 |
|---|---|
| schema_version / course_version | sidecar 1.0 与本版课程 |
| evidence_files | 唯一 reference_identifier、相对 path、course_version、content_sha256、非空 anchor；引用真实材料／量规字节 |
| tasks | 唯一 task_identifier、kind（independent_assessment／post_feedback_recheck）、material_reference、rubric_reference、first_response_items、answer_related_task_identifiers、input_kind、evaluator、initial_evaluation_state；transfer_required 为 false 时写 transfer_not_required_reason |
| transfer_contrast / transfer_review | 基线与新材料的变化声明；review 为 pending，或 reviewed＋reviewer、当前课程版本与真实 evidence_reference |
| assessment_groups | task_identifiers、feedback_release、persistence_policy、resource_policy、recovery_policy；值和必需保护入口见模板 |
| result_policy | 未答不计有效表现、自评不升掌握、开放输入不用关键词评分、首答不被覆盖、再查不追认原首答 |

`feedback_release` 必须为 `all_group_first_responses_persisted_or_assisted`。保存确认不属于知识反馈。evaluator 为 `human`、`self_assessment`、`deterministic` 或 `validated_ai`；deterministic 仅用于其 `input_kind=deterministic`，validated_ai 要有实际 `calibration_reference`。开放且未经验证的状态保持 review_pending。

真实工作正常可用的工具／资料可放入 `resource_policy.declared_normal_resources`，每项写唯一 `resource_identifier`、`evidence_reference` 和 `allowed_use`，将使用边界绑定本课目标。此列表之外的知识帮助遵守受助释放规则。脚本只查声明和引用，是否泄露被测推理仍需实际审阅。

设计交付前运行 `scripts/validate_assessment_integrity.py <文件>`；语义审阅完成后可加 `--require-reviewed` 核对版本与审阅附件。valid 仅指结构、字节绑定与声明，不证明迁移、科学正确或运行锁有效。Demo 实现将组及恢复入口纳入实际浏览器矩阵；审阅 actual tasks/feedback，再测试逐题保存、关联反馈、求助、持久化失败和各恢复路径。保留命令证据，发布与学习效果继续按原 owner。

## 量规与评价条件

量规逐目标设维度、可观察描述、成立和不完整的例子。等级、权重及总分按真实用途决定，不默认四级、等权或统一通关线。需要评分时提前说明规则；自评、反馈量规与效果测量的用途分别记录。

例如，史料解释可以分别看“证据是否支持主张”“是否说明联系”“是否限定时空与材料范围”；语言或作品的维度须重写。不能把文章长度、术语数量、文风与模型相似度当成核心理解。

评价条件写清给定资料、允许工具、帮助定义、提交方式、反馈时机、量规位置及不可判断情况。独立任务可以开放资料和真实工作所需工具；规则依据目标制定，不自动把所有支持算作作弊或求助。

用不同合理表达、部分成立、典型误解和边界答案校准评价者；记录分歧与规则修订，部分真实答案交叉评阅。AI 使用未参与调试的代表性保留样例核对误判、漏判及拒绝判断的情况，并检查适用学科、语言和答案长度等边界。未经验证保持人工、自评或确定性局部检查；模型自己的置信措辞不是评分可靠性证据。

AI 启用决定属于本课 evaluation plan：写明用途与风险、样例分层和来源、独立保留集、误判/漏判/拒判指标及逐项阈值、不可判断策略、审阅负责人和批准证据。模型、提示词、量规或输入契约实质变化时，按清单失效规则重新校准；跨课程不存在默认通用阈值。

检查评价有效性：目标覆盖是否不足，额外阅读／操作负担是否干扰，作答能否证明所需推理，重复评分是否稳定。任务数、评价者数和样本量按用途与风险决定；一次答对只支持该任务上的表现，不证明长期保持或普遍迁移。[LS11]

## 评价分三层

### 设计评审

在制作前检查来源、核心能力、开场、任务、成功标准、误解、证据、反馈与独立应用。对互动作保留、加强、合并或拓展的决定，并写理由。结构脚本通过仅证明字段与引用成立。

### 真实试学

先邀请少量先修知识不同的学习者找问题；人数按条件决定，小规模观察不用于证明学习提升。观察当前问题是否清楚、是否据材料思考、知识与操作困难、反馈后的修订及新任务表现。

“边想边说”可用于找问题，会改变学习过程；与正常条件下的效果测量分开。记录具体困难并修改，再用新的独立任务复查。

### 学习效果与互动贡献

需要评估学习变化时，使用相同目标、难度相近的前后任务和新材料；按需要安排延后检查，记录实际间隔、任务版本与缺失情况。

需要把提升归因于课程或互动时，明确可比版本与主要差异，控制内容、材料、时间及评价条件，采用可比学习者；随机分配时报告基线、退出与缺失。整体课程比较不能证明每个互动都有贡献；检验单项互动时比较保留与简化版本，控制主要变化。

开放解释先以样例校准评价者，对部分答案交叉评阅，并尽量不透露答案所属课程版本。报告各目标表现和不确定性，样本量依据要发现的差异、变异与实际试点确定，不预设通用提升承诺。

执行前写清主问题、主要目标指标、允许评价条件、任务版本、实际延后间隔与分析方式。区分立即表现、延后保持、近迁移及更大情境变化；没有测到的维度明确写未评估。

前后题不能只换名字就宣布等难，可通过共同规范、专家审阅和适当试点检查可比性；条件允许时平衡题目顺序。前后进步可能含练习、测验、选择或其他变化，单组前后结果只描述观察到的变化。需要因果结论时另有合适比较设计，不能以显著性、随机标签或一次 Demo 代替。[LS8、LS11]

## 记录和结论

- 按目标保留首次独立结果、有效依据与推理、典型错误、辅助后修订、下一次独立表现。
- 操作帮助与知识帮助分别记录；求助多不直接说明教学失败，后续独立表现更有解释力。
- 完成、观看、点击、停留与满意度用于体验分析，不能代替学习证据。
- 比例保留分子、分母、未尝试、退出、版本与条件，不只统计最终答对者。
- 区分计划、未执行、已执行证据和结论。没有真实试学或比较数据时，只报告设计判断与运行检查。

评价要点按具体目标设置，不把不可观察的维度记零，不用机械总分或统一通关线掩盖目标差异。
