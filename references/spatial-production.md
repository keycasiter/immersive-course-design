# Three.js空间制作与交接

默认由代码构造几何、材质、光照、相机、动作和实时互动。GLB/Blender不列为环境依赖、必填文件或必要阶段；用户另有指定资产时按实际范围和许可处理。

先读取当前安装的threejs-anime-short/SKILL.md。按当前问题补读其asset-craft、procedural-systems、production-workflow、rendering-choices、render-contracts、motion-and-scale或validation，不复制整份技术手册、案例角色或专用引擎。未安装时仍完成内容与场景规格；制作阶段说明实际能力缺口，在已有授权内选择达到约定品质的可用方法，不能静默降低目标。

## 交接与品质

| 输入 | 实现与检查 |
|---|---|
| 对象的含义、比例、形成/连接依据、可接近视点 | 连续主形、真实厚度、连接/转折、中层结构；参考规律落实到生成/变形函数 |
| 学科规则、单位/坐标、参数范围、演示近似 | 单一规则求值器供可见几何、标签/数值和对象响应使用；有必要的规则写可失败制作测试 |
| 核心感知、景别、画风和目标设备 | 先主次与体积，再材料/光色和可读细节；目标像素稳定，不靠雾/泛光掩盖缺口 |
| 参与方式、时序、锚点、声音与接续 | 动作/接触、直接操作和世界反馈一致；姿态/显隐/标签/FX从状态与时间重建 |

画风逐课确定，不统一强制写实或卡通。人物软组织、复杂结构和变形有独立难点，不因为程序化就以零件拼装替代真实设计。尺寸比较采用合适投影，近景检查曲率/法线/接触，远景检查轮廓和注意力。

先做属于成品范围的代表场景，固定其结构、画面、视点和参与闭环后扩展。一次修改回答一个已定位的问题；必要时用灰模、固定灯或局部对照形成证据，避免无目标整镜穷举。运行预算按设备和实际场景确定，包括影子、反射和后期全帧成本；不定跨课万能FPS或顶点数。
