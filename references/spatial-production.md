# 从体验规格到 Three.js 场景

以代码构造主场景的几何、材质、光照、相机、动作与实时操作。GLB/Blender不列为前提；用户指定资产按实际范围和许可处理。生产顺序见[生产流程](production-workflow.md)，本文件负责把内容交给空间实现。

## 先确定表示与能力

先读已安装 `threejs-anime-short/SKILL.md`，再按造型、程序化系统、渲染、动作或验收问题读取其对应参考。该 Skill 拥有通用技术；本课仍须独立建立对象与规则，借鉴表示和方法，不搬参考角色、场景或专用源码。

依赖不可用时，设计和交接仍可完成；制作阶段先核对当前 Three.js/浏览器/生成工具能力，选择能达到已约定目标的方案。若关键品质确实无法实现，给出具体缺口与可审替代，再由用户决定改变目标；不凭缺 Skill 就停止所有工作，也不静默降低品质。

## 把设计拆成可实现规格

| 设计输入 | 实现决定 | 最小观察/验证 |
|---|---|---|
| 对象含义、结构依据、可接近距离 | 主形/中层/细节用何种几何表示；尺寸、厚度、连接、变形边界 | 轮廓、近景曲率/法线、连接与接触；结构是否支持内容关系 |
| 学科规则、单位与范围 | 纯求值器输入/输出，几何与DOM共享数据，近似独立标注 | 代表值、边界值、关系不变量；规则测试与来源审阅分别进行 |
| 关键感知与目标视口 | 投影/机位、注意目标、对象占屏、明暗与材料层次 | 在实际像素下能辨认关键关系和标签，不靠透视猜精确数值 |
| 动作、对话与自然回应 | 事件/局部时间、对象状态、接触锚点、音频cue、可操作窗口 | 起止状态、等待/打断/返回、声音与动作同步 |

规格放在计划既有区块，复杂生成原理可放项目设计参考并由对应字段引用，不另造一份互动正文。单位、世界锚点、对象ID和状态接口稳定后，模型、镜头、命中、标签与声音才能消费同一结果。

## 落地顺序与修正方法

### 结构先成立

固定能解释核心关系的视点与基础光，先做连续主形、比例、厚度与连接，再补中层结构和可读细节。人物软组织、复杂结构与变形按对象独立设计；程序化不代表把一切拼成基础零件。对精确比较用适合投影，近景看曲率/法线/接触，远景看轮廓和注意力。

### 同一模型接通全部消费者

规则求值器返回对象坐标、派生数值与关系；Three网格、标签/公式、命中锚点和动作响应消费同一结果。世界矩阵更新后投影标签与命中位置；resize、相机变化和恢复也走同一更新路径。不要为页面上的数字再写一份近似公式。具体状态与API见[运行契约](runtime-contract.md)，完整数据交接见[实施示例](worked-example.md)。

### 动作与画面共同解释关系

先确认动作前后和接触，再调整节奏、材料、光影与环境。光线揭示主次与体积，材料区分有意义的结构；文字避开目标与操作范围。画风逐课确定，不能用雾、泛光或零碎装饰掩盖主形和连接问题。有声/人物段按[人物声音](character-and-sound.md)对齐实际音频、姿态与时钟。

### 用定位后的问题驱动修改

先写实际症状及影响：如“切换视点后高线被纸片遮住”，再查模型/坐标、机位、遮挡、材质或布局中哪一层造成。一次修改解决一个已定位问题；必要时用灰模、固定灯、端态或局部对照隔离原因。目标视口的近景、全景和连续动作分别复查，连续失败按生产流程重开前置表示。

## 设备与交接收口

运行预算由本课设备和场景确定，包含影子、反射、透明层及后期全帧成本；以实际加载、操作响应、帧间隔、内存/资源恢复定位瓶颈。保留核心关系和必要细节，再做压缩/简化，复查目标像素稳定性。

交接须能沿同一ID追踪“内容关系 → 规则/生成入口 → 状态/时间 → 网格/DOM/声音 → 实际观察”。代表场景用候选最终品质走通后再扩展；最终放行按[验收](validation.md)执行，顶点数、特效数和脚本通过不代替成品质感。
