# 普通话音色库与整课配音

## 配音输入先完成口语审阅

按[可录制台词与口语审阅](spoken-language-and-review.md)使用同版权威正文，覆盖主线、误解、帮助、重试、返回、恢复和结尾。每段保留稳定台词标识与触发条件，设计说明和导演标签不送入 TTS。文字审阅须先完成；固定声线、自然语气提示或生成成功不能解决书面套话。

文字自审、实际生成音频听审、真人朗读和用户接受在 `verification.md` 分别记录。依实际最终音频重排镜头、动作与字幕，不为匹配旧时长补空话；下述160字上限是供应方输入分段条件，不是写作句长要求。

## 默认生成方式

独立配音默认使用开源 Qwen3-TTS 1.7B，在已部署的 GPU 开发机运行。新候选使用 `Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign`；选定后使用 `Qwen/Qwen3-TTS-12Hz-1.7B-Base` 与固定参考生成全课台词。沿用已有12个候选时直接使用保存的 WAV。画内人物对白可采用支持固定声音参考的原生有声视频，或以固定配音驱动口型；引擎默认值不要求剥离正确的同期人声。

复用已有开发机部署，检查连接、环境、模型和 GPU 占用后调用配音脚本；生成 WAV 与制作记录回传课程目录，再做字幕、混音和时序组装。用户明确要求改变模型或运行方式时，按新的授权更新流程并重新验收。

## 随 Skill 保存的固定资源

音色索引位于 `assets/voice-catalog.json`，WAV 位于 `assets/voice-library/`，路径均相对于本 Skill。索引记录完整声线描述、原始设计指令、参考台词、SHA256、语言、模型、参数与批次种子。参考路径在 JSON 内相对于索引所在目录。

VM/VF 的准确参考台词为：

> 你看，机器已经装好了，车间却还没有开工。棉花、工人和煤都要接到生产里，缺了哪一环，织机都可能停下来。先看看这份记录，你觉得现在最该检查什么？

NM/NF 的准确参考台词为：

> 十九世纪初，英国一些棉纺地区的生产，正从家庭和工坊转向集中使用机器的工厂。机器带来了新的生产方式，也需要原料、动力、工人和资金共同支持。接下来，我们走进一座新工厂，看看这些条件怎样联系起来。

T00 的参考台词独立记录在索引中。参考文字必须对应音频实际内容；不能用自动转写中的同音字替换原文。若试听发现原始参考有错读，制作新的修正版参考并使用新版本与新校验值，不在原编号下静默覆盖。

候选制作模型为开源 `Qwen/Qwen3-TTS-12Hz-1.7B-VoiceDesign`；后续固定参考配音使用 `Qwen/Qwen3-TTS-12Hz-1.7B-Base`。官方实现 `qwen-tts` 的包元数据声明 Apache-2.0；权重使用官方模型仓库，部署时保留其模型许可。VoiceDesign 负责首次设计参考，Base 负责利用固定声音与准确台词生成新内容。反复输入同一描述或同一种子不能替代固定参考。

## 开发机生成

当前项目已有 GPU 开发机部署与12个候选的实际生成记录。复用前检查连接、Python 环境、GPU 占用、模型文件和磁盘；不要重复下载安装。其他机器用现有部署作为参数参考，依其硬件重新验证。

部署发现信息保存在不随Skill分发的本地环境记录或已有授权连接中，使用 course_voice_host、tts_python、base_model_directory、voice_design_model_directory、voice_library_directory、output_directory 等全称字段。可分发参考不保存私有主机、用户名或精确部署路径。复用前通过已有授权验证连接、模型、输出位置和GPU，不重复安装。

已使用的环境：Python 3.10、`qwen-tts==0.1.1`、PyTorch 2.7.1+cu118、Transformers 4.57.3、Accelerate 1.12.0、匹配版本的 torchaudio 和 soundfile。V100 使用 `float16` 和 `eager` attention，不照搬需要 BF16 或 FlashAttention 2 的示例。此前三条一批的候选生成约48—60秒，峰值分配显存约5.2—5.5GB；这是已测小样条件，不作为其他长度或并发的保证。

2026-11-02 已验证 Base 固定参考调用：使用 VM01 原始 WAV 生成“我们先核对这份记录，再决定从哪里开始。”，输出24kHz单声道、4.16秒，模型加载4.97秒、生成13.92秒、峰值分配显存4.81GB。WAV解码正常；Whisper small 转写为“我們先核對這份記錄再決定從哪裡開始。”，与目标台词仅繁简和标点差异。此记录验证调用与文本内容，跨段音色和自然度仍待实际试听，不代表整课音频已替换。

把 `scripts/generate_course_voice.py`、`assets/voice-catalog.json` 和完整 `assets/voice-library/` 一起放到开发机，保持目录关系。使用部署环境的 Python：

```bash
"<tts-python>" "<skill-root>/scripts/generate_course_voice.py" --check

"<tts-python>" "<skill-root>/scripts/generate_course_voice.py" \
  --voice-id VM01 \
  --model-dir "<qwen-base-model-directory>" \
  --text "我们先核对这份记录，再决定从哪里开始。" \
  --output "<existing-output-directory>/scene-response-vm01.wav"
```

`<skill-root>` 为本 Skill 所在目录。脚本可用 --list 列候选、--text-file 读UTF-8台词、--preflight 仅检查参考/权重/路径、--batch-file 复用一次模型加载。逐段按句意拆分，每段不超过160字。生成前验证单文件或分片索引与全部权重并哈希；临时WAV与JSON经解码后发布完整结果。任何输出路径、JSON或别名均不得覆盖索引和固定参考；--overwrite只适用于已有生成结果。

失败输出有 generation-status，恢复先核对原任务。JSON publication_status=complete、WAV哈希一致且任务状态complete才可使用；普通文件存在不证明完整发布。具体异步、GPU与预算规则见[媒体任务运行与恢复](media-job-execution.md)。

批量制作可在同一模型进程使用官方 `create_voice_clone_prompt(ref_audio=..., ref_text=..., x_vector_only_mode=False)` 缓存同一角色参考，再把该 prompt 传给 `generate_voice_clone`；缓存须按参考哈希和模型版本区分。语气或情绪改变后仍核对身份，不把新增描述当作新的声线。

## 课程中的连续性

在 `media-plan.md` 固定“角色标识 → 音色编号 → 参考路径与SHA256 → 模型与参数 → 录音/生成版本”。旁白单独登记。角色在开场、主视频、资料引用、答对、答错、求助、重试和结尾使用同一参考，台词清单给每条音频稳定标识。

多角色要实际参与：写清各自提供的证据、提出的问题、学生行动后的对应回应，以及如何接回主线。人物引语由对应角色配音，知识整理用固定旁白；不能把多角色设计全部交给一个讲述声线。

视频内对白和视频外反馈使用同一角色参考。视频生成器支持声音参考时输入已选声线；正确原生对白可以保留。采用新的原生声线时另登记候选标识、完整原声台词和参考WAV，不冒称已经匹配原有VM/VF/T00。相同提示词或种子不能保证不同请求间身份一致。

生成器暂不支持声音参考时，可在同一源视频内录制主线和一条完整反馈，再提取整句反馈音轨，作为同源衔接小样；不得拼词造句，也不得由这条小样推断整课声线已可扩展。后续使用该候选原声的固定参考或授权录音生成新台词，并实际连续试听。

需要改换视频声线时，用实际最终配音驱动同步口型，核对音画开口、闭口、停顿与镜头长度；只替换音轨或把闭嘴人物留在画面中不算完成。知识旁白可独立配制；人物画外反馈须已建立同场位置，等待画面不伪装成其正在说话。环境音、对白、旁白分轨；室内外混响和方位变化保持人物身份。

先连续试听开场、含术语/数字的讲解、提问、误解反馈和返回接续，检查本音色库语言、完整台词、漏字重复、断句、音色与自然度。本库为普通话项目预设；其他语言使用对应参考、索引和实际小样，不照搬中文检查结论。自动转写只发现问题；哈希不证明听感一致，未经校准的嵌入相似度不作验收依据。

混音可从约 -18 LUFS、真峰值不高于 -1.5 dBTP 起步，结合音乐和现场声校准。固定参考保存未混音 WAV，课程成品另存，响度归一化不覆盖声音参考。

验收记录分别标明参考文件完整、生成成功、台词/普通话核对、跨段音色试听、混音与口型时序。未实施项写未执行；使用新机器、模型、参考或处理方式后重验受影响片段。
