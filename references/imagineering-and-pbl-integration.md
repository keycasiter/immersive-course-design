# Imagineering × PBL 整合框架

进入本文件前，先读取[内容设计质量与 Imagineering 路由](content-design-quality.md)。该文件负责候选内容、学科真实性和体验增量；本文件只负责判断 Imagineering 与 PBL 如何组合，不负责证明内容本身有趣或教学有效。

本文件定义两套框架在本 Skill 中的分工。它们可以组合，但不能互相替代。读取本文件前，先读取[PBL 前置适配筛分](pbl-fit-screening.md)；只有筛分结果为 `pbl_full`、`pbl_bounded` 或 `project_extension` 时，才把 PBL 条款纳入课程设计。

## 1. 两套框架的职责

### Imagineering：体验和生产层

Imagineering 负责回答：

- 学习者进入什么世界、场景或问题空间；
- 世界有哪些主题、规则、对象、人物和环境线索；
- 学习者在其中能做什么；
- 行动如何产生可感知反馈；
- 艺术、故事、空间、媒体和工程约束如何共同成立；
- 如何通过原型、测试和修订把体验变成可运行的作品。

本 Skill 使用的是公开的 Imagineering 教育化转译，不声称复现任何组织的全部内部流程。它是沉浸课程的默认体验/生产层候选，不是 PBL 的同义词。其稳定骨架是：

```text
世界/主题
→ 对象/人物/环境
→ 学习者行动
→ 感官与系统反馈
→ 工程约束
→ 原型
→ 测试与修订
```

### PBL：学习和教学层

PBL 负责回答：

- 学习者要解决什么有意义的问题；
- 需要持续探究哪些资料和概念；
- 学科知识如何进入项目；
- 学习者有哪些真实的选择和表达权；
- 如何反思、接受反馈并修订；
- 最终作品面向什么真实受众公开呈现；
- 如何评价内容、技能、过程和作品。

本 Skill 采用 Gold Standard PBL 的七个项目设计要素：

1. 有挑战性的问题或驱动问题；
2. 持续探究；
3. 真实性；
4. 学习者声音与选择；
5. 反思；
6. 批评与修订；
7. 公开产品。

## 2. 组合后的课程契约

完整的 Imagineering × PBL 课程必须同时有：

```text
驱动问题
→ 进入一个有规则的体验世界
→ 通过视频、对象、资料和互动持续探究
→ 形成一个持续演化的学习者作品
→ 接受反馈并修订作品
→ 面向真实受众展示和解释
```

视频主线可以固定课程时间线，但不能代替 PBL 的持续探究、作品、反馈和公开展示。互动可以保持局部、可逆、不改变课程主线；学习者的选择应体现在证据、解释、作品结构、表达方式或修订策略上。

如果筛分结果为 `imagineering_only`，只使用 Imagineering 的世界、对象、行动、反馈、工程约束和原型要求；不要求驱动问题、跨阶段作品、公开产品或 PBL 修订循环。仍须通过内容质量 owner 的学科真实性、证据可见性和体验增量门。

## 3. 必须写入设计纲要的整合字段

新课和重大改稿必须记录：

| 字段 | 要求 |
|---|---|
| `driving_question` | 一个需要证据和解释才能回答的问题，不能只是知识点问答 |
| `authentic_context` | 真实或有意义的任务背景 |
| `authentic_audience` | 作品要面向的真实/模拟真实受众 |
| `persistent_learner_artifact` | 跨多个 Beat 持续形成的作品或对象 |
| `learner_voice_choice` | 学习者能决定的内容、证据、结构、表达或策略 |
| `inquiry_plan` | 要查找、比较、回访和解释的资料/概念 |
| `critique_revision_loop` | 反馈来源、修订点、再提交条件 |
| `public_product` | 最终公开呈现的形式和质量标准 |
| `experience_world` | 主题、对象、规则、感官线索和进入方式 |
| `engineering_constraints` | 时间、空间、资源、媒介、设备和运行约束 |

如果没有 `persistent_learner_artifact`，课程可以是体验式互动课，但不能宣称已经实现完整 PBL。

## 4. Imagineering 层与 PBL 层的映射

| Imagineering | PBL | 交付要求 |
|---|---|---|
| 世界/主题 | 真实性、驱动问题 | 说明学习者为什么进入这个世界 |
| 对象/人物/环境 | 持续探究 | 每个对象承载可观察的资料、关系或约束 |
| 学习者行动 | 声音与选择 | 行动不是装饰点击，必须影响作品或解释 |
| 感官反馈 | 形成性反馈 | 反馈说明对象发生了什么以及为什么 |
| 工程约束 | 挑战性问题 | 约束必须进入任务，而不是只写在幕后 |
| 原型 | 作品 | 作品有版本、状态和质量标准 |
| 测试/修订 | 批评、反思、修订 | 至少一次有证据的修改和再提交 |
| 体验呈现 | 公开产品 | 作品面向明确受众解释和展示 |

## 5. 视频主导课程的具体落地

对于 `video_led_web`：

```text
视频事件
→ 场景对象/资料/环境线索
→ 驱动问题的一个子问题
→ 学习者行动
→ 互动反馈
→ 持久作品更新
→ 返回视频事件
```

每个必需 Beat 至少说明：

- 它推进驱动问题的哪一部分；
- 学习者观察或操作哪个对象；
- 学习者获得哪条资料、关系或约束；
- 学习者如何更新持续作品；
- 反馈如何帮助下一次探究；
- 是否需要回访此前概念；
- 返回视频后保留什么状态。

互动不必改变历史/科学/故事主线，但必须对学习者自己的作品、证据选择、解释或表达产生可见影响。

## 6. 作品类型

持久作品可以是：

- 证据地图；
- 解释性模型；
- 设计方案；
- 实验记录；
- 调查档案；
- 关系图；
- 作品集；
- 导览、展板或公开讲解；
- 经过版本修订的报告、脚本、原型或页面。

作品不是隐藏数据库记录。学习者必须能看到当前版本、缺失部分、反馈、修订历史和最终呈现目标。

## 7. 准出检查

设计确认前检查：

- 是否有驱动问题，而不是只有章节标题；
- 是否有真实或有意义的受众；
- 是否有跨 Beat 持续形成的作品；
- 是否存在学习者真实的选择；
- 是否至少安排一次资料回访或概念回访；
- 是否有形成性反馈；
- 是否有反思、批评和修订；
- 是否有公开产品和质量标准；
- 世界、对象、行动、反馈和工程约束是否共同支持学习目标；
- 视频、互动和作品之间是否通过稳定 ID 关联。

若只有视频、热区、弹窗题和结尾答案，应标记为 `interactive_explainer` 或 `experience_prototype`，不能称为完整 Imagineering × PBL 课程。
