# 可感知体验蓝图

本文件是 `interactive_web + video_led_web` 的设计交付契约。它解决“教学目标和交互规则已写出，但使用者仍不知道最终体验如何落地”的问题。

## 交付目的

课程设计阶段不要求已经生成正式视频，但必须让课程设计者、视频、声音、视觉、前端和教学评审者能够复原学习者的一次体验：

`看到什么 → 听到什么 → 在哪里暂停 → 点击/进入什么 → 做什么知识动作 → 画面和反馈怎样变化 → 如何回到视频`

没有正式媒体时，所有内容标记为 `planned`、`prototype` 或 `unverified`；不得标记为 `accepted`。

声明沉浸作用时，同时按[沉浸评价](immersion-evaluation.md)建立 `immersion-plan.json`：体验意图与适用构念 → 具体声画/互动决定 → 本蓝图的场景、Beat、shot 和资产 → 正反判据 → 评审与试学。蓝图呈现“看到/听到/做了什么”，plan 说明“怎样判断预期体验是否成立”；复用原标识，不另造媒体或教学 schema。

## 每个 Beat 的最低字段

| 字段 | 说明 |
|---|---|
| `beat_id` | 与课程、媒体、页面、事件和清单共用的稳定 ID |
| `learner_intent` | 学习者此刻要理解、判断、比较、操作或表达什么 |
| `video_segment` | 起止时间、主视点、段落作用和前后 Beat |
| `shot_sequence` | 镜头顺序、景别、构图、主体、动作、转场和教学损失 |
| `voice_script` | 旁白/对白逐句文本、说话者、声音状态、字幕用途 |
| `visual_evidence` | 学习者必须看到的对象、关系、状态或变化 |
| `special_frames` | 暂停帧、证据帧、开放帧、反馈帧、返回帧 |
| `hotspot` | 出现时间、锚定对象、屏幕区域、安全区、触发条件和输入方式 |
| `interaction_surface` | 直接控件、场景卡、文档阅读、确定性工具、3D 或 360° 等 |
| `entry_view` | 进入交互后的第一屏构图和必要信息 |
| `learner_action` | 知识动作；“点击热区”只能是入口，不是学习证据 |
| `state_changes` | 进行中、正确、错误、求助、修订和退出时的可见变化 |
| `return_state` | 视频时间、画面、视点、字幕、声音、焦点、草稿和对象状态 |
| `asset_refs` | 视频、音频、字幕、确定性图层、模型、史料和原型引用 |
| `acceptance` | 内容、视觉、声音、交互、连续性、移动端和无障碍条件 |

## 五张最小预览帧

每个必需互动点必须有以下材料之一：

1. 实际视频小样；
2. 逐帧分镜板；
3. 关键帧序列；
4. 静态交互状态板；
5. 可点击低保真原型。

材料至少呈现：

- `entry_frame`：进入前的实际视频帧；
- `hotspot_frame`：热区出现后的画面；
- `interaction_frame`：互动第一屏；
- `feedback_frame`：错误、求助或结果状态；
- `return_frame`：返回视频后的状态。

文本表格可以补充这些材料，但不能替代所有材料。若本轮只完成文本设计，应把范围派发为 `local_design` 或 `illustrative_prototype`，而不是完整视频课程设计。

## 3D/360°的可感知要求

提出 `spatial_3d` 或 `spatial_360` 时，除目标和选择理由外，必须提供：

- 进入前的锚定帧；
- 进入后第一视图和导航方式；
- 学习者需要观察或操作的空间关系；
- 至少一个状态变化或反馈；
- 等价二维路径；
- 返回视频的具体时间和状态。

仅写“进入 3D 模型”或“进入全景场景”不构成设计。

## 设计评审问题

- 评审者能否不运行代码就画出主要镜头和互动状态？
- 旁白每一句是否有对应的画面证据？
- 热区是否锚定当前视频对象，而不是悬空按钮？
- 互动第一屏是否足以让学习者开始行动？
- 错误/求助后改变的是知识状态，还是只有按钮颜色？
- 返回视频时是否保留了对象、答案、字幕、声音和焦点？
- 视频、交互和页面团队是否可以直接从同一 Beat ID 开始生产？
