# 课程前置澄清与递进卡点

本文件拥有新课/重大改稿的前置澄清、充分输入复用和 Demo 独立验收条件。生命周期与失效重放由[流程状态](orchestration-and-status.md)拥有，机器字段由[生产清单](production-manifest.md)拥有。

## 固定阶段

课程先关闭澄清门，再确认完整设计，然后实现并验收 Demo。正式批量生产同时要求有效 Demo 与最难媒体闭环。编排卡点和七个生产阶段分别记录，按流程 owner 的事件重放推导。

## 阶段 1：接收用户输入

先原样记录用户目标，再区分：

- 已明确：主题、学习者、用途、交付形态、内容边界、设备、时长、媒体和评价要求。
- 可核实：教材/来源、工具能力、已有产物和运行条件。
- 未决：会改变目标、教学深度、参与权限、交付终点或制作成本的决定。

此阶段允许做来源核实和既有产物盘点；不允许制作 Demo、正式页面、正式媒体或把设计假设写成已确认决定。

## 阶段 2：澄清问题

对每个仍会改变方案的未决决定，逐项提问。每个问题必须同时包含：

1. 当前理解和为什么这个决定会改变后续设计；
2. 推荐答案；
3. 推荐理由与主要取舍；
4. 两个或更多实质不同的可选方向（适用时）；
5. 用户实际选择、理由和受影响范围的记录位置。

问题一次只解决一个决定。不要发送无法逐项回答的总问卷，也不要用 Agent 自己的推荐答案代替用户选择。

## 阶段 3：澄清完成卡点

只有同时满足以下条件，才能标记 `clarification_confirmed`：

- 主要学习者/起点已确认，或用户明确接受待诊断方案；
- 最终独立表现和成功证据已确认；
- 必需内容边界和来源版本已确认，或用户明确授权以可追溯的临时来源进入设计草稿；
- 使用条件、学习者参与权限和本轮交付终点已确认；
- 关键决定已有明确用户授权。充分输入或既有有效决定能完整覆盖以上条件时，引用原输入形成摘要，记录 `confirmation_basis=sufficient_explicit_input` 并继续；仍需决定时，记录用户对摘要的确认，使用 `user_summary_confirmed`。

两条路线均绑定实际输入/对话证据、范围版本和澄清摘要；记录者与实际确认者分别保存。用户沉默、Agent 推荐和草稿存在不能关闭门。充分输入不重复索要摘要批准。

## 阶段 4：进入 Demo

澄清有效、完整设计已达到 `design_confirmed` 后进入 Demo。分镜路线使用 `storyboard_events` 确定性事件载体，真实视频路线使用 `video_clock`；运行模式和适用检查见[前端契约](frontend-prototype-contract.md)。完整 Demo 必须满足：

- 全部目标、场景、Beat、知识动作、独立应用和无障碍等价路径已覆盖；
- 页面、错误、求助、修订、关闭/返回、刷新恢复、桌面和窄屏路径已实现；
- Demo 运行入口、证据文件和浏览器验收范围已登记；
- 任何未完成项只能是正式视频生成、视频时钟绑定或视频接入后的回归。

澄清未确认时，不能创建 Demo 页面，即使页面暂时标为草稿或原型。

## 阶段 5：Demo 验收卡点

只有以下证据齐全，才能标记 `demo_accepted`：

- 用户/实际负责人明确确认当前 Demo 版本和范围；
- `validate_course.py`、`validate_production.py --joint` 及适用页面/运行时检查通过；
- 浏览器实测覆盖正常、错误、求助、修订、返回、刷新恢复、键盘/触摸、桌面/窄屏和静音/字幕等价路径；
- 验收记录写明版本、范围、证据文件、未完成正式视频差额和风险。

Demo 验收前不得启动正式媒体批量生产、成品组装或“最终成品”验收。

## 阶段 6：正式成品

`demo_accepted` 后才能进入 `production_in_progress`。正式成品阶段只补齐已确认的正式媒体、真实视频时钟绑定和接入回归，不得借生产阶段重新决定课程目标、世界、任务、反馈或评价边界。若这些内容变化，回退到受影响的澄清/设计门。

## 变更与回退

以下变化使 `clarification_confirmed` 失效并要求重新澄清：换诗目/教材、改变学习者或用途、改变最终表现、扩大内容范围、改变参与权限、改变设备/无障碍约束或改变交付终点。

以下变化使 `demo_accepted` 失效并至少回退到 `demo_in_progress`：改变页面交互、反馈/修订/恢复、独立应用、无障碍路径、事件顺序或替代资产。正式媒体替换只按生产清单的媒体回归规则处理。
