# 全流程编排与状态

本 Skill 是从课程设计到效果验证的编排器。每一阶段只在前置证据成立后推进；尚未执行的阶段保持未完成，不用计划、脚本通过或素材存在代替。

## 生产阶段与编排卡点

`current_status` 保留唯一七阶段序列：

`design_draft → design_confirmed → media_sample_confirmed → production_complete → functional_accepted → learner_trial_complete → effect_evaluated`

澄清和 Demo 使用独立 `approval_subjects` 与确认门，经相同的 `reconfirm/invalidate` 历史生效。设计确认依赖澄清；Demo 确认依赖澄清和全部设计范围。进入 `production_complete` 的事件当时必须已有有效 Demo 与媒体小样确认；小样确认不能替代 Demo。

`workflow_state` 从重放结果派生：澄清未确认为 `clarification_in_progress`；澄清有效且生产阶段尚未设计确认为 `design_draft`；设计确认后未建立运行入口为 `design_confirmed`，已建立 Demo 为 `demo_in_progress`；Demo 确认后且尚未生产完成为 `demo_accepted`；生产完成及以后与 `current_status` 相同。`clarification_confirmed` 是澄清门的状态说明，`production_in_progress` 是 Demo 通过后的工作说明，两者不另造生命周期枚举或推进事件。

新课与重大改稿的前置条件和实际用户证据读取[澄清 owner](clarification-gate.md)。草稿可在输入整理阶段建立；完整设计确认和任何 Demo 实现都要求澄清有效。只有草稿时交付设计文件。

状态不得跳过。项目可以停在任一状态，但不能把后续状态写成已通过。未完成 `clarification_confirmed` 时，Demo 必须阻断；未完成 `demo_accepted` 时，正式成品生产必须阻断。修改已确认范围内的教学逻辑、代表性视觉规则或核心媒体契约时，退回受影响的确认门；局部文件重做不自动要求重审全部课程。

## 两道人类确认门

### 设计确认

确认材料至少包含：

- 学习者画像、来源和必需目标。
- 实际开场、完整场景、教学资料、台词、任务、反馈、补救和新情境应用。
- 媒体分工、评价方案、无障碍等价路径和制作风险。
- `verification.md` 与通过结构校验的蓝图。

记录确认人、时间、版本、范围和证据引用。Agent 不得自行代签。

确认还须绑定实际目标、教学内容、任务判定、补救和独立应用的内容指纹。范围使用稳定 `scope_identifier`，每个范围有独立 `subject_version`。总包 `course_version` 与范围版本分开：其他范围或素材变化可更新总包版本，不能据此取消未改变的确认，也不能借用总包版本掩盖本范围内容变化。

### 最难媒体闭环确认

选择最能暴露全课风险的一条链，而非最容易的镜头。至少覆盖“正式有声视频或主媒体 → 当前对象入口 → 核心操作/模型 → 对应反馈 → 返回现场并恢复声音和状态”。同时检验视觉圣经、角色连续性、写实/风格目标、声音、移动端构图和等价路径。

媒体闭环与 Demo 两项都确认后才批量生产。若课程没有视频或3D，选择其最难代表性交互链，并说明选择依据。

分别绑定实际小样和制作约定的范围版本与指纹。小样包含运行入口、实际覆盖资产和资源依赖；制作约定包含视觉圣经、实际声音参考、口型和连续性规则。文件同名或请求参数相同不能证明素材未变。

### 确认有效性与改动边界

| 改动 | 处理 |
|---|---|
| 目标、教学内容、任务判定、补救或独立应用变化 | 受影响设计范围重确认；检查依赖此内容的小样是否也需重确认 |
| 视觉、声线、口型或连续性制作约定变化 | 受影响媒体范围重确认；无关设计范围保留原确认 |
| 已确认的小样本身变化，包括其入口、对白、音视频或交互依赖 | 小样重确认，不用“只是重新生成”豁免 |
| 同一教学内容与制作约定下重做其他素材 | 只重新验收该素材及实际受影响的字幕、入口或接续；不自动重审全课 |
| 不改变教学含义的错字或排版 | 保存明确的差异核对记录，保留确认；数值、单位、否定、答案、条件等变化不能默认归入此项 |

未改变的范围保留原确认人、时间、证据和指纹；新确认追加至归档，不覆盖原记录。`advance`、`invalidate`、`reconfirm` 事件重放决定当前绑定与状态。失效依据真实依赖撤销后续结果，重新确认本身不跳级推进。具体字段和非语义修订记录见[生产清单契约](production-manifest.md)。

澄清或设计失效退回 `design_draft` 并传播撤销依赖确认；媒体约定/小样失效退回 `design_confirmed`；Demo 独立失效最多保留 `media_sample_confirmed`，编排回到 `demo_in_progress`。子任务继承调用父清单的同一完整重放与当前文件核对；任何直接、传递失效或被替换的旧确认均不能继承。

追加前保留上一份不可修改的清单快照，校验时使用 `--previous-manifest`；历史必须是原快照的完整前缀，确认归档亦如此。哈希链和本地声明不验证人的身份，原对话/审阅证据仍需保留。

## 规则层级

- **硬性约束**：状态门、来源边界、目标覆盖、可用性、安全、权利与隐私、正式资产验收。违反即阻断。
- **项目默认值**：当前工作区推荐的语言、工具、模型、页面外框和交付路径。用户或项目可显式覆盖。
- **设计建议**：场景顺序、媒体形式、时长、角色数量和交互方式。根据学习目标调整，不作为配额。

冲突时按“用户明确要求与法律/安全约束 → 硬性约束 → 已确认设计 → 项目默认值 → 设计建议”处理，并在生产清单记录覆盖原因。

## 阶段执行

| 当前阶段或工作说明 | 执行重点 | 下一步的证据 |
|---|---|---|
| `design_draft` | 先完成需求澄清，再建立画像、证据登记、目标、脚本、评价、体验蓝图和可感知预览契约 | 澄清记录完成；视频课逐 Beat 的镜头、声音、互动状态可复原；设计材料齐全、联合检查通过且人类明确确认 |
| `design_confirmed` | 锁定设计版本和范围，准备 Demo | 设计确认记录；允许进入 Demo |
| `demo_in_progress` | 实现完整非视频体验，登记正式视频差额 | Demo 运行入口、完整内容覆盖和浏览器验收证据 |
| `demo_accepted` | 实际负责人验收 Demo 的正常/异常/恢复/无障碍路径 | Demo 明确确认；允许进入正式成品生产 |
| `production_in_progress` | 补齐正式媒体、时钟绑定并完成组装 | 所选范围正式资产完整 |
| `production_complete` | 功能、恢复、响应式、声音与等价路径验收 | 实际步骤、截图/日志和缺陷关闭 |
| `functional_accepted` | 真实学习者试学和修订 | 观察、版本、问题与复查 |
| `learner_trial_complete` | 按目标执行效果评价准备与实施 | 方法、样本、结果与不确定性 |
| `effect_evaluated` | 记录效果评价结论与不确定性 | 评价过程和结论独立归档 |

付费调用、发布、外部消息和远程写入仍按用户授权执行；阶段确认不自动授予这些权限。

`effect_evaluated` 只表示评价过程完成，不自动转换成 `supported`。零效果、负效果或证据不足的评价都可以完成过程，具体结论必须单独记录为 `supported`、`not_supported` 或 `inconclusive`，不采用跨课程通用效应阈值。
