# 课程3D资产生产：图像重建、Blender整理与网页验收

异步生成、下载恢复、取消、重试与预算按[媒体任务运行与恢复](media-job-execution.md)执行；任务成功与正式结构准出分别记录。

方法来源：[Atlas 3D技术调研](https://bytedance.larkoffice.com/docx/Db2CdSnDKoF2Fyx7BptcsUYOngc)，读取日期2026-11-02，文档revision 151；已核对正文和7张画板的原始文本节点。下文将调研中的主体分割、Seed3D纹理模型、任务与产物记录方法用于课程制作，并补充课程所需的结构、动作和连续性验收。整理规则与验收是课程要求，不能写成调研已经验证了教学模型。

## 先确定资产任务

写明学生要观察或操作什么、可接近的机位、尺度与精度、部件关系、活动范围、切换状态和人物参与。按已有课程设计确定结构依据，不让生成结果决定历史器物、科学结构或机构规则。

在已授权的制作范围内，复用既有GPU开发机、Blender环境、模型与脚本。仅更新方法时不启动生成；实际生产先查工具、凭证、SDK、模型、输入限制、输出格式和计费是否可用。保持[媒体、角色与互动连续性](media-interaction-continuity.md)：视频、360°、3D与任务保留同一角色、对象、空间和行动链。

## 按输入选择路径

| 输入与目标 | 制作路径 | 必须检查 |
|---|---|---|
| 清楚的单主体图 | 整图预处理 → 图生3D → 下载纹理GLB | 背景是否被重建、主体是否完整，输入尺度与方向是否合适 |
| 多对象或有文字/说明线的图 | 原图点选/框选 → SAM等主体分割 → 透明PNG → 图生3D | 选区坐标、掩码与透明边界，文字和邻近物体是否混入 |
| 只有文字描述 | 使用实际支持文本的提供方，或先制作有依据的参考图再走图生3D | Atlas的文本路径使用Hyper3D；不能将Seed3D的图像路径当成已验证的文本能力 |
| 精确内部结构、薄件或可动机构 | 依据可靠参考，在Blender直接建模，或将生成外观拆分后重建关键部件 | 单图补出的背面/内部不能作为依据；生成单块网格不等于可动装配 |

Seed3D可作为图生3D候选，其他已验证提供方可以替换。图像重建用于建立外形和纹理初稿；Blender承担整理、补建、材质、光照、机构动画和最终导出。

## 主体分割与透明切图

1. 保留原图及校验值。将页面点位与框选换算回原图像素坐标，处理缩放、裁切与留白；框选保存完整边界，中心点只作兼容字段。
2. 点选使用SAM point prompt，框选使用SAM box prompt。Atlas的原始流程使用邻近点击点的连通域过滤、合理掩码选择及形态学close/open；具体SAM版本和阈值以实际环境核对。
3. 在原图上叠合检查mask，确认选中了目标主体。最大面积启发式可能选中背景或邻近物体；轴、传动带、细杆等薄结构须单独检查，不能被形态学清理删除。
4. 将mask写入alpha，得到透明PNG cutout。去除文字、标注、背景和无关物体，保留关键连接处、空洞与轮廓；分割失败时修改选区、修mask或换图，再提交。
5. 每次尝试关联原图、输入cutout、mask、选区坐标、对象元数据和校验值。Atlas保存的 `input.png`、`mask.png`、`object.json` 可借鉴为制作记录；课程另保留原图和最终cutout，方便定位问题与复现。

图像中有一个物体，不代表它应作为一个不可分割的网格。先按操作目标确定独立部件，必要时分别生成外观或在Blender拆件。

## 生成、状态与产物

调研的Seed3D路径通过Ark SDK创建任务并轮询状态。文档使用 `client.content_generation.tasks.create()` / `get()`，任务内容包含参数文字与图像地址；实际使用前按当前受支持SDK核对接口和模型能力，不照搬内部服务的路由、地址或部署标识。

调研推荐参数为：

```text
--subdivisionlevel medium --fileformat glb --use_original_alpha true
```

这只是调研参数起点。核对当前提供方是否仍支持细分等级、GLB及alpha输入。`Raw`、`Shaded`是可选项，不能当作必需配置；Shaded可能带入原图明暗，需检查是否影响网页重新打光，不能自动视为完整PBR材质。

按任务和资产分别记录状态：

- 生成任务：queued → running → completed / failed，并记录错误、尝试、实际时长与结果。
- 资产制作：生成成功 → 已整理 → 已核对结构/动画 → 已导出 → 浏览器已验收。任务completed只表示生成阶段结束，不直接标记教学可用。
- 多次生成：参考Atlas的Job与Session历史，增量写入每次产物和状态；版本保留，不用后来的结果覆盖前一尝试。

轮询采用当前接口允许的间隔、退避、超时及终态处理；Atlas的3秒间隔不作为未来固定配置。恢复时先查询原任务，避免重复提交造成额外费用。失败时保留错误与已完成产物，再决定重试或换输入。

成功后及时下载实际GLB和纹理；若提供方返回压缩包，检查内容并解包，不能只改后缀。校验文件格式、可解析性、纹理引用、文件大小与SHA256，再写入资产记录。临时 `file_url` 用于取回产物，课程运行使用持久化的本地或已授权存储资产。

文档记录的5—8分钟/次、约2.4元/次仅为调研参考，预算以当前计费与实测为准。累计全部尝试、变体和实际计费；单次生成时长不等于包含排队、重试、Blender整理的交付耗时。

凭证通过受支持环境或凭证服务提供。Skill、模板和制作说明只记录配置字段与占位符，不保存密钥、私有端点、局域网Demo地址或账号标识。

## Blender整理与机构动画

1. 导入GLB，统一方向、单位、比例、原点和对象命名；对照参考修复缺面、漂浮面、畸形、重复网格和错误背面。
2. 根据教学目标拆成稳定命名的可选部件。给旋转部件设置真实枢轴与局部坐标；生成网格融合了多个活动件时，重建连接与活动部分。
3. 检查UV、法线、纹理、透明边缘和材质尺度，补充近景倒角、金属粗糙度、木纹与接触阴影。把不可导出的复杂材质烘焙或转换成GLB支持的材质；避免把原图阴影重复叠加到实时光照上。
4. 根据资料制作确定的状态与动画，登记输入、连接条件、输出和暂停/重放规则。需要物理仿真时单独验证；外形生成不证明传动、行程、齿轮关系或科学机制。
5. 制作角色参与与场景锚点：模型、视频和全景中的名称、尺寸、位置、机位、光向相接；有对白或引导时角色实体在场，动作对应当前对象。
6. 保留可编辑 `.blend`、纹理、参考与最终GLB。导出后重新导入检查部件、材质和动画，静态预览图与文件清单不能代替动作验收。

本课动力资产的应用：生成可用于蒸汽机、织机外观初稿；轴系、驱动端、织机输入及枢轴按机械参考整理或重建。断开时驱动端转而织机静止，接通时输出随动；不得把生成模型整体旋转当成传动。此例不限定其他课程的资产或规则。

360°场景可以复用已验收部件，但单物体GLB不等于完整全景。院落仍需在Blender建立正确空间，使用全景相机渲染实际投影，检查方向、接缝、地平线与实体人物参与。

## Three.js接入与验收

网页通过GLTFLoader等实际支持的加载器使用GLB，用AnimationMixer或明确对象变换控制动画、通过射线拾取对应部件。浏览器负责加载、实时光照、镜头、操作和事件；模型编辑源保留在Blender。

记录稳定部件标识、可操作目标、枢轴、动画clip、状态转换、相机与人物锚点、字幕/声音事件及恢复规则。支持触摸和键盘，拖拽有等价点选；返回恢复原画面、方向和记录。

| 准出 | 实际证据 |
|---|---|
| 输入与重建 | 原图/cutout/mask对照、主体无误、薄件与关键连接完整，补出结构有依据 |
| Blender资产 | 部件与枢轴正确、材质和近景细节可用、状态与机构动作无穿插脱节 |
| GLB交付 | 实际文件可重新导入、纹理不丢失、标识/动画可找到，校验值与版本一致 |
| 网页画质与性能 | GLB与Blender参考对照；目标桌面/手机实测首屏加载、操作流畅度、内存和纹理表现，按结果优化 |
| 学习与现场 | 学生操作产生正确对象变化和角色回应；视频/全景/模型转换、字幕声音、暂停与恢复不断链 |
| 状态与费用 | 失败/恢复/重复提交处理、尝试记录和实际消耗明确；未执行项不标通过 |

压缩与减面须保留关键结构和近景品质；选择纹理、网格压缩时同时配置兼容解码器并实测。只在真实运行与完整现场小样通过后把资产标为可用。
