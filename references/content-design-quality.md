# 内容设计质量与 Imagineering 路由

本文件是课程内容质量与 Imagineering 体验/生产层的唯一 owner。`SKILL.md` 只负责派发；`instructional-design.md` 负责目标、证据、示范、练习、独立应用与评价；`imagineering-and-pbl-integration.md` 负责 Imagineering 与 PBL 的组合边界；本文件负责内容候选的发散、筛选、学科真实性、体验增量和质量门。

## 1. 两层契约

课程必须同时满足：

```text
结构契约：组成部分、字段、覆盖、状态和验收是否完整
内容质量契约：问题是否值得解决、是否符合学科、学生是否真正行动、是否产生证据
```

结构完整不能推出内容有趣。内容有趣也不能替代目标、证据和教学闭环。质量分数用于筛选和比较设计版本，不是学习效果证明。

## 2. Imagineering 的准确位置

本 Skill 使用公开的 Imagineering 教育化转译，不声称复现 Disney 内部流程，不要求 IP、固定画风、危机开场、角色数量或自由漫游。

Imagineering 是**体验与生产层**，默认适用于需要把知识放入可感知世界、对象、行动、反馈或工程约束的课程。它回答：

```text
世界/主题
→ 对象/人物/环境
→ 学习者行动
→ 可感知反馈
→ 工程约束
→ 原型
→ 测试与修订
```

它不自动等于 PBL。PBL 是**学习与教学组织层**，是否启用由 `pbl-fit-screening.md` 决定。

允许的四种组合：

| `experience_design_mode` | 使用内容 | 不要求 |
|---|---|---|
| `imagineering_only` | 世界、对象、行动、反馈、工程约束、原型 | 持久作品、公开展示、长周期探究 |
| `project_extension` | 基础教学后增加一个有作品的项目任务 | 整门课项目化 |
| `pbl_bounded` | 驱动问题、受限探究、作品局部迭代、模拟受众 | 完整长周期 PBL 的全部范围 |
| `pbl_full` | 持续探究、持久作品、选择、批评修订、公开产品 | 无额外默认项 |

`video_led_web` 是运行层，不是教学法；不得用它替代 `experience_design_mode` 或课程设计。

## 大胆设计，小心求证

课程创作与证据核验分两遍完成。**大胆设计**负责提出值得评审的明确方案；**小心求证**负责校准事实、能力和验收主张。两者同时严格，但不在每段正文里互相打断。

### 第一遍：大胆设计

围绕已确认目标，先写出有立场的课程选择：

- 选择一个最强承载方案，写清对象、行动理由、可见后果和持续变化；备选与取舍集中写一次，不让主稿在多个方案之间摇摆。
- 把教学材料、题干、台词、反馈、场景变化和学生作品写成可直接评审的实际内容。未知制作参数不妨碍先完成体验契约。
- 让情境、人物、视觉和互动服务学习，但允许它们有鲜明气质、节奏和惊喜。只要没有越过来源、安全和学习证据边界，就不因尚未制作或尚未试学而主动削弱创意。
- 对可逆的风格、叙事和媒体决定采用清楚默认值，先完成完整方案，再用评审修订。不要把每个创作决定写成“可选、可能、仅供参考、仍需确认”的并列菜单。

完成条件：不读作者解释，评审者仍能说出这门课最鲜明的体验是什么、学生做什么、行动改变什么、最后留下什么。

### 第二遍：小心求证

设计成形后，再逐项核对来源、推断、工具能力和验收：

- 会改变知识准确性、学生安全、权利、评价结论或下一行动的边界，写在对应材料或反馈旁。
- 版本状态、未执行检查、人工确认、工具能力、媒体可用性和效果限制，集中进入 `verification.md`、清单或评价记录；正文只引用会改变当前设计的结论。
- 同一限制只写一次。事实/推断/创作的总体披露放在来源入口，具体任务只保留当前判断需要的边界。
- 结构通过、设计判断、媒体实测、教师确认和学习者结果分别记录；缺证据时降低结论强度，不降低设计具体度。

完成条件：每项重要主张都有合适证据状态，且移除核验台账后，课程主稿仍然完整、具体、可制作。

### 防御性内容删减

交付前逐段检查：

1. 这句话是否改变学生看到的材料、能做的动作、反馈、评价或制作决定？
2. 若只说明“尚未执行、不能证明、仍需确认”，是否已经在核验台账中记录？
3. 同一边界是否在来源、正文、分镜、评价和结尾重复出现？

第 1 项为否且第 2 或第 3 项为是时，从课程正文删除或缩成一次集中说明。必要边界不删；重复的自我免责、过程旁白和通用免责声明删掉。

### 回归走读

- **正例**：一门文学课明确选择一种世界、一个持续作品和具体互动后果，主稿直接呈现完整课堂；来源状态和未执行项只在核验区出现一次。
- **反例**：每场都重复“画面仅供教学、未证明学习效果、仍需教师确认”，角色和页面不断播报待审状态，主稿大半篇幅用于解释自己不能证明什么。
- **通过标准**：删除集中核验区后，正例仍可制作；删除反例中的防御句后，教学含义基本不变，说明这些句子原本不应占据正文。

## 3. 内容候选先发散，再收敛

先按[语境知识编织](contextual-knowledge-weaving.md)建立核心内容的语境图和贯穿线，再按[学科教学与体验选择](subject-pedagogy.md)定位核心知识点的难点，读取适用指南，比较教法与表征。已有候选中必须包含语境主干和教学机制的真实差异，不能只更换世界、身份、关键词或控件；不为此另加候选数量。

在写剧情、场景、视频提示词或页面前，先围绕每个核心目标生成至少 5 个 `content_candidate`，至少覆盖 3 种问题类型：

- `observation`：发现变化或证据；
- `explanation`：解释机制、关系或作用；
- `decision`：在约束下选择并说明取舍；
- `repair`：诊断失败、修改方案并验证；
- `creation`：为受众制作满足条件的作品；
- `transfer`：在新材料或新条件下应用方法。

候选必须写：

```yaml
candidate_id:
subject:
grade_band:
objective_identifier:
problem_type:
learner_problem:
subject_move:
key_constraints:
learner_actions:
student_product:
likely_misconceptions:
transfer_condition:
experience_world:
immersion_increment:
source_boundary:
```

`subject_move` 是本学科真实动作，例如语文找证据、数学建模、科学控制变量、历史比较史料、信息科技调试。只写“探索、体验、帮助角色”不算学科动作。

教学选择复用现有字段，不新增 schema：`likely_misconceptions` 写当前知识点的具体认识难点；`subject_move` 写所选机制中的判断和操作；`key_constraints` 写单位、尺度、语境等条件及表征对应；`learner_actions` 与 `student_product` 写可见过程和学习证据；`immersion_increment` 写关键时刻、声画/空间决定和行动后果；`transfer_condition` 写撤架与实质变化；`reviewer_notes` 引用主稿中的教法对照、适用理由和来源范围。结构脚本验证原有字段，教法匹配仍由实际内容审阅判断。

## 4. 内容质量评分

每个候选按 0–4 分评分：

| 维度 | 0 分 | 2 分 | 4 分 |
|---|---|---|---|
| `disciplinary_authenticity` | 与学科无关 | 只有表面术语 | 核心动作就是该学科真实工作 |
| `problem_tension` | 没有问题 | 有问题但答案显然 | 信息或条件不完整，必须判断、试验或解释 |
| `learner_agency` | 只播放/点击 | 选择现成答案 | 构造、取舍、修订或表达改变结果 |
| `evidence_visibility` | 看不到思考 | 有答案无依据 | 产物显示依据、关系、条件或变化 |
| `progression` | 场景堆叠 | 有练习但无撤架 | 示范→引导→独立→修订→迁移清楚 |
| `memory_value` | 平铺直叙 | 有局部变化 | 发现、后果、作品或真实选择由学习动作产生 |
| `contextual_fit` | 无来源，或由表面词语联想出主线 | 背景可信但只作讲解/装饰 | 来源清楚；语境主干连接核心材料，学生用它重读、修订并限定结论 |
| `production_feasibility` | 依赖不可得能力 | 可做但代价高 | 低成本替代也能验证核心学习动作 |

加权分：

```text
质量分 =
disciplinary_authenticity × 20%
+ problem_tension × 15%
+ learner_agency × 15%
+ evidence_visibility × 15%
+ progression × 15%
+ memory_value × 10%
+ contextual_fit × 5%
+ production_feasibility × 5%
```

换算为 100 分：

- `85–100`：可进入课程蓝图；
- `70–84`：必须完成内容重写或学科教师审阅；
- `60–69`：只保留为备选；
- `<60`：淘汰。

硬门槛：

- 学科真实性 `<3`；
- 学生能动性 `<2`；
- 证据可见性 `<3`；
- 现实/文化适切性 `<3`；
- 语境丰富的内容没有“核心材料 → 语境揭示 → 学生重读/重做 → 后续判断”的完整链；
- 具名作品、人物、事件、理论或发明缺少用户提供的背景资料，且没有定向检索形成可定位的 `context_source_packet`；
- 没有独立学生产物；
- 必需学习互动删除后目标、证据和教学动作完全不变（观察/示范片段与纯氛围元素不适用此项）；
- 依赖无来源事实或把创作设定当作事实。

## 5. 学科与场景的发散参考

这些是候选生成的参考，不是固定模板或配额。

| 学科 | 真实动作 | 可用内容问题 | 学生证据 |
|---|---|---|---|
| 语文 | 找证据、解释作用、改写、迁移 | 哪个词改变了画面/态度？ | 引用文本的解释或修订作品 |
| 数学 | 建关系、估算、验证、优化 | 条件改变后方案怎样变？ | 图示、计算、方案和理由 |
| 科学 | 观察、假设、控制变量、解释 | 哪个变量导致现象变化？ | 实验计划、数据、模型解释 |
| 历史 | 比较史料、判断立场、限定因果 | 这份材料能证明什么，不能证明什么？ | 有来源的证据链和边界 |
| 地理 | 读图、定位、比较空间、预测 | 为什么空间条件导致差异？ | 标注地图和解释 |
| 英语 | 语境表达、回应、修正、迁移 | 对方没听懂时怎样重说？ | 语言产物和对话修订 |
| 信息科技 | 分解、调试、测试、权衡 | 为什么程序只在某个输入下失败？ | 修改、测试记录和解释 |
| 艺术 | 观察形式、控制变量、创作、比较 | 怎样让受众看出某种关系或情绪？ | 版本作品和设计理由 |
| 体育 | 感知动作、策略调整、反馈修订 | 哪个动作改变了表现？ | 动作记录、策略和复盘 |
| 道德与法治 | 识别情境、权衡规则、论证 | 多个价值冲突时如何说明选择？ | 主张、依据、限制和回应 |

跨场景参考：

```text
观察现场：发现变化并记录证据
实验室：控制变量并解释结果
档案室：比较来源并限定结论
工作室：设计、制作、测试、修订
调度中心：在约束下决策并承担后果
对话现场：表达、倾听、回应、改写
维修现场：复现故障、定位原因、最小修复
田野调查：采样、分类、解释、报告
议事/法庭：主张、证据、反驳、权衡
展览/发布：面向受众综合表达并根据反馈修改
```

为场景登记学习作用或体验作用；体验作用可以是空间延续、在场感、情绪或注意进入，按下一节审查。

## 6. 体验增量检查

对每个视频、角色、动画、空间、热点和道具填写：

```yaml
element_identifier:
value_kind: learning | experience | both
learning_objective_identifiers:
learner_action_enabled:
evidence_changed:
experience_effect:
required_for_learning:
engineering_constraint:
replaceable_by:
why_keep:
removal_loss:
```

先区分作用，再回答：

1. 删除该元素后，学习目标是否仍可完成？
2. `learning/both`：保留后增加什么观察、比较、解释、反馈或证据机会？按目标关联动作与证据。
3. `experience/both`：保留后怎样延续场所、对象、情绪或注意？写出可走读的预期效果及删除损失。
4. 低成本材料能否先验证学习动作？体验效果能否通过静态、低动态与正常路径的比较审阅？

`experience` 可以独立进入媒体计划，`required_for_learning=false`；不可独有承载必需知识。保持视频主舞台和保护区，限定运动与声音注意预算。页面动态背景的层级由 `video-surface-contract.md` 管理，时间/状态由 `video-presentation-contract.md` 管理。

无控制承诺的观察或示范片段可以只承担呈现、理解与连续性，不要求逐镜修改对象或留存学生产物；整门课程仍须为必需目标提供可接受的学习证据。对于确有控制承诺的互动，反馈必须兑现它。

## 7. 内容质量审查

### 设计者审查

逐项回答：

- 学生最可能在哪一刻提出真实问题？
- 哪个条件会迫使学生改变判断？
- 错误暴露了什么具体缺口？
- 学生最后留下什么值得保存或展示的产物？
- 哪个部分主要服务体验？它的删除损失与注意力代价是否值得保留？

### 学科教师审查

只看原文/材料、目标、教学序列、教师提问、学生任务、反馈和修订，不看视觉。检查学科真实性、事实边界、年龄适切性和评价标准。

### 教师走课审查

未参与设计的教师必须能回答：

1. 这节课要让学生学会什么？
2. 第一项有效提问是什么？
3. 学生答错时下一句怎么说？
4. 从哪个学生产物判断学会？
5. 结课时学生留下什么？

答不出任一项，课程保持 `content_review_pending`。

### 沉浸增量审查

分别走读原版、移除氛围版与低动态版。学习作用看目标/动作/证据机会是否变化；体验作用看进入、空间连续、情绪、注意与恢复是否变化。两者分别记录，不能因教学证据相同就自动淘汰氛围，也不能用体验评分代替掌握证据。

## 8. 与教学、PBL、页面的边界

| 文件 | 负责什么 | 不负责什么 |
|---|---|---|
| 本文件 | 候选发散、内容质量、Imagineering 体验增量、内容门 | 不定义学习目标 schema、PBL 全部字段或视频时钟 |
| `instructional-design.md` | 目标→证据→示范→练习→撤架→独立→评价 | 不决定故事世界和美术表现 |
| `pbl-fit-screening.md` | 判断是否适合完整 PBL、受限 PBL或项目延伸 | 不把所有 Imagineering 课变成 PBL |
| `imagineering-and-pbl-integration.md` | 两层框架组合及作品/受众要求 | 不取代内容质量评分 |
| `video-surface-contract.md` | 播放/暂停/反馈/返回的页面视觉状态 | 不证明课程有趣或学生学会 |
| `course-evaluation.md` | 取证、解释、反馈、再查和效果评价 | 不以完成率证明内容质量 |

## 9. 准出状态

每个核心候选和完整课程使用以下状态：

```text
candidate → content_review_pending → content_approved
                              ↘ content_revise
```

只有 `content_approved` 才能进入 `design_confirmed`。结构校验通过不能跳过内容审查。课程试学后发现内容无聊、情境迷失、学科动作缺失或学生无法解释时，回退到 `content_revise`，不通过继续打磨 UI 解决。

## 10. 可执行内容门 1.1

从[内容模板](../assets/content-design-quality.template.json)开始，列出 `core_objective_identifiers` 和已声明的 `source_identifiers`。每个本轮核心目标分别有至少五个候选、三种声明的问题类型，已选候选覆盖全部目标。联合检查与 scoped blueprint 核对目标和来源；局部设计仅包含本轮 scoped 目标。模板保留一个候选以提示格式，必须展开后才能通过内容结构检查。

`content_review` 包含实际教师 `review_owner`、`reviewed_version`、`reviewed_at`、`reviewed_content_sha256`、非空 `evidence_references` 和逐项 `evidence_files`（reference_identifier/path/content_sha256）。payload 指纹是除 `content_review` 外整个质量文件的 canonical JSON SHA256；证据路径相对质量文件。运行 `validate_content_quality.py <file> --show-content-fingerprint` 只计算指纹，教师审查后据实际确认记录填写，不能由 Agent 生成审阅事实。

manifest 的 `content_design.reference_identifier` 指向 `evidence_files` 中 `kind=content_design_quality` 的质量文件；教师记录另以 `kind=content_review` 注册。模式、选定候选和审阅引用与文件一致。`validate_production.py` 对草稿执行结构检查，对 `design_confirmed` 及以后执行严格内容门；`--joint` 再核对目标/来源。设计确认指纹包含质量文件及实际审阅文件字节，改候选或证据即失效，不能靠只更新 manifest 哈希保留原确认。

1.0 文件保留在历史产物中。当前准出必须迁移到 1.1 并补实质审阅；不自动将旧 `approved` 当作新版通过。机械检查只证明声明、覆盖与字节绑定，评分正确性、材料真实性、教师身份和学习效果仍靠实际审阅与试学。
