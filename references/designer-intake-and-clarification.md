# 设计者输入与逐问澄清

在设计课程之前，与课程设计者建立足以做出教学决策的共同理解。问题、推荐答案和建议方向均根据本课输入与当前回答动态生成；澄清选择持续约束后续设计和落地。先读输入，探索能查到的事实，沿会改变方案的分支逐问推进。此过程面向设计者；课程里的学习者开场、诊断和帮助另行设计。

## 适用范围

- 新课：从课程用途、学习者与最终表现建立设计依据。
- 重大改稿：保留未受影响的已知条件，只处理改变目标、难度、内容、参与、评价或交付的分歧。
- 恢复任务：读取原回答及当前版本，继续未解决分支，不重问。
- 指定素材、错字或局部控件修改：先复用已确认课程条件，只有缺口影响本次结果时提问。
- 方法或 Skill 维护：讨论方法的使用者、触发、边界与行为，不让用户回答不存在的课程画像。

## 先把输入转成决策依据

读取用户原输入、指定教材或资料、既有课程设计与确认范围、项目默认配置和当前可发现的工具能力。生成简短内部记录，区分：

- 明确输入：设计者已给定的目标、偏好、限制及本次修改。
- 设计者确认：设计者已回答的具体取舍；保留原回答依据。
- 材料核实：来自教材、课程版本、设备或工具检查的事实。
- 建议假设：Agent 提出的可逆默认及理由，尚未得到回答。
- 未决：会影响方案的未知或相互冲突条件。

不要把“希望适合初学者”当作已经验证的真实画像，不把项目工具偏好当作设计者指定的学习体验。新输入与旧确认冲突时检查影响范围；设计者可以修改意图，受影响正式确认仍按既有状态规则处理。不要索取无关身份或个人敏感信息。

## 按输入生成问题、推荐和多个方向

每次提问前，把当前输入中的学科、主题、用途、目标、学习者、来源、场景和约束，与已有回答一起分析。找出仍有歧义的具体决定及其后果，据此生成问题；不把候选维度名称直接转成固定问法。

- 问题引用与它相关的输入，例如“你希望全程宏观呈现，同时让学习者解释多方关系”，再指出尚未明确的参与方式。不要询问输入已确定的路线。
- 推荐给出适合这门课的具体答案或方案，说明哪些已知条件支持它、怎样帮助目标、会带来什么取舍。不能只有“推荐A，因为更合适”，也不能把设计建议伪装成已有事实。
- 存在多个成立方向时，提供数量适当的备选；每个方向写清实际任务或体验、适用条件及对后续设计的影响。方向应有实质差异，不把名称或画风变化冒充教学选择，不机械凑出三个。
- 多个方向可以体现不同学习重点、任务、参与权限或叙事策略，但每次仍只解决一项决定。与明确约束冲突的方向应说明冲突，不能直接推荐。
- 设计者可以选推荐、选其他方向、组合有兼容性的部分，或给自定义答案。记录实际选择与理由；组合会产生矛盾时，只澄清该矛盾，不强迫使用预设选项。
- 输入不足时，推荐保留成立条件，先问能够确定这些条件的问题。前一回答改变条件后，重新判断下一问题和推荐，不继续发送已经过时的问卷。

## 候选澄清分支

以下维度是检查线索，不是问卷配额。只对输入没有解决且会改变本课决策的部分提问；每次从表中选择一个具体问题，不一次发送整表。

| 分支 | 需要共同理解的内容 | 何时值得问 | Agent 如何给推荐 |
|---|---|---|---|
| 课程用途与应用场景 | 为什么需要这门课；现有困难；学后在哪种情境使用；本课在单元中的作用 | “了解一下”“做得有趣”等不能说明要解决什么问题 | 建议一个与内容相符的应用问题，说明它会怎样决定核心任务 |
| 学习者与起点 | 主要学习者、可激活的先修、语言与阅读/操作能力、常见误解、差异和必要支持 | 起点不同会改变术语、任务难度、节奏或帮助 | 优先确定主要群体与必需先修；未知困难列为待诊断，不以年龄代替能力 |
| 最终任务与成功标准 | 学完能独立解释、判断、操作或产出什么；到何种程度算成功；能力范围 | 目标只有“理解/掌握”，或目标与时间不匹配 | 给出一个可观察整任务及成立表现，再讨论最有竞争力的替代；不把播放或点击当掌握 |
| Imagineering 与 PBL 适配 | Imagineering 体验世界、对象、行动和工程约束是否成立；PBL 是否具备驱动问题、真实/模拟真实受众、跨阶段作品、学习者选择、探究、反馈修订和公开产品 | 课程声称采用项目制、Imagineering 或沉浸式作品生产，但只有视频、互动题或一次性结课作业；或学习内容高度收敛、不适合持续项目 | 先推荐 `imagineering_only`、`project_extension`、`pbl_bounded` 或 `pbl_full`；固定事实/主线，按内容开放程度配置证据、解释、表达和修订方式 |
| 内容、深度与来源边界 | 必需知识和不讲内容、教材/版本、学科表述、证据可信度、事实与创作/模型的界限 | 来源冲突、深度不明或情境会改变事实理解 | 先核对来源，建议与任务匹配的深度；不能向设计者询问可查史实代替核实 |
| 学习与使用环境 | 自学/教师主持/协作，连续或分段使用，总学习时间，手机/电脑、网络、必要无障碍条件 | 环境会改变任务组织、交互、声音、支持或恢复方式 | 区分视频时长与总学习时长，根据已知使用方式建议；沿用已说明的设备条件 |
| 学习者参与与权限 | 学习者负责什么，哪些判断或操作产生什么后果；可改变与不可改变的对象/事实 | “沉浸”“参与剧情”未说明知识动作，或设计暗示不合理权限 | 推荐与目标对应的取证、比较、预测、试验、修订或解释；历史事实保持不变，模拟后果标明边界 |
| 叙事尺度与体验要求 | 哪些关系必须整体呈现，哪些证据需要局部深入；角色、视点、情绪强度与明确风格限制 | 存在教学效果相近的路线取舍、强烈偏好或明显不匹配 | 按目标、知识关系、背景和来源比较路线；尺度、镜头视点和交互深度分别设计 |
| 支持、节奏与自主程度 | 基础支持、初始尝试/示范、求助、错误后的修订、难度差异、自主探索范围 | 试错代价、先修差异、特殊支持或必须遵守的教学安排会改变主线 | 根据困难与代价推荐支持及撤除方式，不要求设计者代选每道题或框架 |
| 评价目的与条件 | 自学反馈/课堂诊断/正式考核，允许资料与工具，独立程度，开放答案由谁判断，是否有真实试学和追踪 | 不同评价用途会改变任务、反馈时机或证据成立条件 | 将过程参与、受助表现和独立应用分开；建议相称的任务与量规，不承诺未经验证的自动评分 |
| 交付、制作与明确偏好 | 本轮产物与终点、最终使用形态、已有可复用资产、工期、外部调用约束及必须遵守的体验偏好 | 设计稿/原型/成品混淆，或指定形态与资源有实质冲突 | 复用授权与实际工具检查，说明约束对方案的影响；常规技术选择自主处理，付费或外部操作沿用授权规则 |

“主题”和“课程目标”也属于该树：先确定主题与必需范围，再把目标转成任务与成功标准。上表中的支持、叙事和制作细节是派生分支；输入充分时由 Agent 推荐，不把每个教学决策交回设计者。

## 如何选择下一问

默认按依赖推进：

`用途与主要学习者 → 最终表现 → 内容与评价边界 → 使用条件 → 参与和叙事 → 支持与制作取舍`

顺序随材料调整。明确的考试标准可先约束目标；固定设备或极短时长可先排除不可行路线；已有完整画像和目标就从实际分歧继续。

选择能消除最大后续分歧、且无法由资料核实的问题。优先解决“解释机制还是识别部件”，不要先问“用几个视频还是几个 3D”。每次只询问一项决定；不把受众、时长、风格和目标塞成一个复合问题。选项是不同决策路径，不是堆叠要用户逐项填写的要求。

每问包含：

1. 这个问题为什么会改变方案，用一句话说明。
2. 一个具体问题；必要时给两三个可比较的选项。
3. 根据当前输入生成的推荐答案、依据与主要取舍；存在实质备选时同时说明多个方向，供设计者选择或修正。

推荐结合已知材料，不能先认定某个年龄、宏大开篇、第一人称短剧、全课 3D 或教学框架。信息太少时推荐“先明确主要学习群体”等决策方向，避免伪造具体用户条件。设计者不是教学专家时，用可理解的任务例子和后果比较，不要求其提供理论名称、技术参数或完整目标表。

收到回答后，更新受影响分支，核对矛盾，再决定下一问。回答含糊时，给出一个可观察的解释或任务样例继续核对；不要原样重复抽象问题。已经回答的条件不再问，除非新输入改变它。

## 何时继续设计

当主要学习者及起点、核心表现与成功证据、必需内容边界、使用条件和本轮终点足以支撑方案时，整理简短澄清结论并明确发给设计者确认。新课/重大改稿必须等设计者明确确认澄清摘要后，才能进入设计草稿和 Demo 制作；它们可以来自原输入或已核实材料，但不能由 Agent 单方面假设关闭澄清卡点。

- 视觉风格、具体控件、镜头和常规支持策略等可逆细节，采用有依据的建议并注明。
- 无法替设计者决定的关键意图，提出一个问题并等待；同时继续资料核实、已有条件整理及独立工作。
- 用户明确要求“按推荐假设先出稿”时，只能形成澄清材料或非制作性设计草案，并标记 `clarification_pending`；不能进入 Demo、页面实现、正式媒体或成品生产。
- 缺少可查事实或工具能力时先探索；缺少真实学习者证据时保留未知与诊断计划，不编造画像或效果数据。
- 不设置固定问题数、必答维度数或额外的“澄清通过”状态。不在信息充分后再问“可以开始吗”。

在 `design-outline.md` 的“设计者输入与澄清结论”记录决定、依据、建议和未决影响；按下一节将其带入实际产物。无需另存逐字访谈或新建一套课程 JSON 契约。正式设计确认仍绑定完整材料的范围、版本与指纹；澄清期间的“同意这个目标”只确认该目标取舍。

## 澄清选择贯穿设计与落地

`design-outline.md` 是澄清结论的统一来源。为会影响后续产物的关键决定设置稳定 `decision_identifier`，例如 `decision_learner_participation`；保留相关输入、问题、推荐及备选方向、设计者实际选择、理由、状态、适用范围与当前版本。已有明确输入可直接登记，不虚构一次访谈。建议未获采纳、方向被排除和决定被修改时，不能仍当作当前选择。

按以下链路把选择转成可核对的实际内容：

`设计者输入与选择 → 目标/难度/成功标准 → 教学任务与叙事 → 媒体和交互计划 → 制作与实现 → 成品核对`

| 阶段 | 选择怎样进入产物 | 核对什么 |
|---|---|---|
| 课程设计 | 引用相关决定标识，写成具体目标、先修支持、内容边界、节拍、任务、反馈和独立应用 | 任务与实际资料是否体现所选能力、深度、权限和路线 |
| 媒体计划与制作 | 将选择转成分镜信息任务、场景/角色边界、声音、媒体选型和生成要求；制作交接引用实际设计位置 | 实际候选视频、声音或模型是否符合选择，不能仅看提示词 |
| 页面与交互实现 | 选择转成可见对象、知识动作、信息层次、反馈、进度与返回；引用本版实现位置 | 实际操作是否实现所选参与方式、设备条件和支持，模板不能覆盖选择 |
| 评价 | 选择转成最终任务、量规、允许工具、帮助定义、评价方式和反馈时机 | 所选能力是否有相称的成功证据，未验证评价能力不能被选择本身证明 |
| 验收与交付 | 在 `verification.md` 建立决定到实际设计、媒体、页面和评价证据的追踪 | 分阶段填写本版内容审阅或运行证据；未执行不填通过 |

各产物只引用与自身相关的决定及具体位置，不逐文件复制整份访谈。交给其他技能、生成工具或实现人员时传递这些选择及约束，不能只传课程标题。纯设计阶段写清后续实施要求；有正式实现授权时继续核对实际文件和运行行为，不能用设计追踪代替落地。

允许在选择范围内自主细化镜头、控件、练习表达和制作方式。细化应保持所选目标、内容深度、参与权限、叙事方向和评价条件，并在追踪中说明理由。出现新证据或不可行条件时，说明具体冲突、受影响决定与替代建议；需要改变设计者的核心选择时，只确认该变化。已明确授权的修订直接更新结论和受影响产物，正式确认失效按既有规则处理；不新增全课批准门。

恢复任务和进入新阶段时读取当前有效结论，保留旧选择的变更依据，不让过期或未采纳方向回流。验收发现偏差时修正实际产物或解决具体选择冲突；只补一句“已充分参考澄清结果”不能消除偏差。

## 典型输入与下一步

| 设计者输入 | 下一步示例 | 选择理由 |
|---|---|---|
| “做一门光合作用沉浸课” | 先问主要学习者已有怎样的基础；推荐先确定主要群体与必需先修，再给具体任务 | 未知起点会同时影响术语、机制深度和叙事，不能直接假定高中或零基础 |
| “初中生，已经学过细胞，15分钟手机自学，用所给教材解释光照变化为什么影响光合作用” | 核对教材后推荐解释新条件下的结果，给出实际任务和支持建议；范围已充分就直接设计，只有教材与输入不能确定是否扩展多因素条件时才澄清该范围 | 保留明确的解释目标，不重问受众、先修、设备、时长或已经确定的最终能力 |
| “四年级，12分钟课堂小组课，重点是分数比较” | 若范围不明，只问是否包含分母不同的情况；推荐以已知先修和教材为依据确定范围 | 范围决定策略、表征和难度，比剧情视点更早 |
| “西安事变，全程宏观叙事，面向熟悉事件经过的学习者，根据双方立场解释和平解决条件” | 保留宏观路线，核实先修与史料；若参与方式未明，可给“史料对照后解释关系”和“标明边界的条件模拟”两个方向，依目标推荐前者。选择前者后，写入实际史料比较任务、宏观关系反馈与独立解释评价 | 问题和推荐来自本课目标；全程宏观也能深度参与，未选模拟或局部短剧不能回流实现 |
| 同一输入中，设计者选择了备选的“条件模拟”，并要求与真实经过对照 | 记录实际选择，保留宏观视角与历史事实；设计有来源依据的条件变化、模型边界与后果比较，落实到实际交互，最终要求解释模拟与史实的差异 | 后续以实际选择为依据，不能因 Agent 原先推荐史料对照而又做回纯阅读课 |
| 已给明确受众、先修、独立任务、量规、教材、环境和授权终点 | 引用输入形成澄清摘要，直接设计；后续只问新出现的关键冲突 | 澄清是建立依据，不是强制发问 |
| “只改第三场的提示，其他不动” | 读取第三场任务和既有条件，按影响范围修改；没有教学分歧就直接完成 | 不重启整课画像和目标访谈 |

这些例子检验提问和决策方式，不证明课程有效。检查新规则时用不同完整度、学科和范围的输入走查：问题和推荐是否随输入改变、下一问是否只含一项决定、已知是否复用、多个方向是否有实质差异、实际选择能否追踪到任务和成品、未决是否影响后续、充分输入是否能直接继续。
